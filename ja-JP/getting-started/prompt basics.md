# プロンプトの基本

<Callout type="info">
プロンプトとは、Kimi に送るテキスト形式の指示です。質問、説明、要件の一覧、あるいはタスク全体のブリーフにもなります。Kimi はプロンプトをもとに、あなたの意図を理解し、回答を組み立て、タスクを実行します。

要するに、**聞き方が Kimi の答え方を決めます。** 明確で具体的なプロンプトほど、ほとんどの場合、より正確で価値のある回答につながります。
</Callout>

## 良いプロンプトを作る4つの基本要素

### 1. 役割と背景を伝える

あなたが誰で、どのような状況にいるのかを Kimi に伝えると、適切な深さとトーンで応答しやすくなります。

| あいまいなプロンプト | より良いプロンプト |
|-------------|--------------|
| AI について記事を書いて | 私はテック系メディアの編集者です。一般読者向けに、わかりやすく引き込まれる文体で、2,000語程度の AI 解説記事が必要です |
| データ分析を手伝って | 私はマーケットアナリストです。この Excel ファイルのチャネル別コンバージョン率を、前月比の変化に注目して分析してください |

### 2. タスクを具体的に説明する

説明が具体的であるほど、修正のやり取りは少なくて済みます。良いタスク説明には、一般的に次の要素が含まれます。

- **何をするか**: 明確な操作（分析する、要約する、翻訳する、生成する、比較する、など）
- **出力形式**: 表、リスト、段落、コード、Markdown など
- **範囲と制約**: 文字数・語数、項目数、期間、地域範囲など
- **品質要件**: 学術的なトーン、会話調、簡潔、詳細など

<ComparisonBlock
  wrong={"この記事を要約して"}
  correct={"この記事を英語で3つの箇条書きに要約してください。各項目は50語以内にしてください"}
/>

### 3. 例や参考情報を示す

形式に関する明確な期待がある場合は、Kimi に例（few-shot）を示すと非常に効果的です。

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "会議メモを次の形式で整理してください:\n\n会議トピック: xxx\n参加者: xxx\n主な決定事項:\nxxx\nxxxアクション項目:\n[ ] xxx (担当者: xxx, 期限: xxx)",
    },
  ]}
/>

### 4. 複雑なタスクは手順に分ける
複雑なタスクでは、作業を小さなステップに分け、Kimi を順に導きます。

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "競合分析レポートが必要です。次の手順に従ってください:\n国内の主要競合上位3社と、その中核機能を挙げる\n各社の価格戦略を比較する\n各製品の強みと弱みを分析する\n自社製品の差別化に向けた提案を示す",
    },
  ]}
/>

## 実践的なコツ
### フォローアップと反復を活用する
最初の回答に満足できない場合は、そのまま追加で指示しましょう。文脈を最初から説明し直す必要はありません。
- "2つ目のポイントを詳しく説明してください"
- "トーンをよりフォーマルにしてください"
- "データ出典を追加してください"
- "別の観点から再分析してください"
### ファイルやリンクを活用する
Kimi は PDF、Word 文書、Excel ファイル、画像などのアップロードに対応しています。URL を直接貼り付けることもできます。ファイルとプロンプトを組み合わせると、効率が大幅に高まります。
| タスク | プロンプト例 |
|------|---------------|
| PDF を要約する | "この PDF の要点を要約してください" |
| データを分析する | "この Excel データをもとに売上傾向を分析してください" |
| URL から抽出する | "リンク先の記事を読み、重要なポイントを抽出してください" |

### 出力形式を指定する
必要な形式を Kimi に正確に伝えましょう。
| ニーズ | プロンプト例 |
|------|---------------|
| 比較表 | "A と B のメリットとデメリットを表で比較してください" |
| コード出力 | "これを Python で実装し、コメントも付けてください" |
| 構造化リスト | "番号付きリストで整理し、各項目は20語以内にしてください" |
| Markdown | "見出し階層を付けて Markdown 形式で出力してください" |

### 継続的な好みにはメモリを使う
繰り返し使う好みや要件がある場合は、Kimi の **メモリ** 機能に長期的に覚えさせることができます。
- "私は React スタックを好むフロントエンドエンジニアだと覚えておいてください"
- "常に英語で、Markdown 形式で返信してください"
- "技術的な質問に答えるときはコード例を含めてください"

<Callout type="tip">
こうしておけば、同じことを何度も伝える必要はありません。Kimi は今後の会話で、これらの好みを自動的に反映します。
</Callout>

## よくある間違い
| 間違い | より良い方法 |
|---------|----------------|
| 関係のない複数のタスクを1つのメッセージに詰め込む | 独立したタスクごとに新しいセッションを始め、文脈を整理しておく |
| プロンプトがあいまいすぎる（例: "何か書いて"） | 何を、誰に向けて、どのような文体で、どのくらいの長さで書くのかを指定する |
| 最初の出力で完璧な結果を期待する | まず下書きを生成し、その後フォローアップで反復改善する |
| AI の出力をファクトチェックしない | 日付、データ、事実に関する主張は必ず確認する |

## すぐ使えるテンプレート
コピーしてカスタマイズすればすぐに使える、プロンプトテンプレートをいくつか紹介します。
**ライティング**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "[topic] について、[target audience] 向けの [article type] を約 [xxx] 語で書いてください。\n要件: [style/format/focus areas]",
    },
  ]}
/>

**分析**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "[subject] を分析し、[key dimensions] に重点を置いてください。\n出力形式: [table/chart/report]\n結論と推奨事項を含めてください。",
    },
  ]}
/>

**翻訳**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "次の内容を [target language] に翻訳し、[academic/conversational/business] のトーンを維持してください。\n専門用語については、括弧内に原語も併記してください。",
    },
  ]}
/>

</Callout>
