# カスタマイズとリファレンス

Kimi Code CLI には豊富なカスタマイズ機能が用意されており、AI の動作やワークフローを用途に合わせて調整できます。

## 設定ファイル

Kimi Code CLI はグローバル設定ファイルとして `~/.kimi/config.toml` を使用し、TOML と JSON の両方の形式に対応しています。次の項目を設定できます。

- **API プロバイダーとモデル**: さまざまなモデルプロバイダー、API エンドポイント、キーを設定します。
- **デフォルトモデル**: 使用するデフォルトモデルを指定します。
- **実行時パラメーター**: タイムアウト、concurrency、出力形式などの実行時設定を調整します。

> `/config` コマンドを使うと、設定ファイルをすばやく開いて編集できます。

## AGENTS.md によるプロジェクト設定

プロジェクトのルートに `AGENTS.md` ファイルを置くことで、AI にプロジェクト単位のコンテキストを提供できます。

- **プロジェクトの背景**: プロジェクトの機能、アーキテクチャ、技術スタックを説明します。
- **ビルド手順**: 依存関係のインストール、プロジェクトのビルド、テストの実行方法を記載します。
- **コード規約**: 命名規則、ディレクトリ構成のルール、コードスタイルの方針を示します。
- **特記事項**: セキュリティ上の制約、パフォーマンス要件、その他の重要な注意点を記載します。

`/init` コマンドを使うと、AI がプロジェクトを自動でスキャンし、初期版の `AGENTS.md` を生成します。ファイルを手動で編集し、プロジェクト固有の情報を追加することもできます。`AGENTS.md` ファイルは任意のサブディレクトリに配置できます。AI は関連する設定を自動的に読み込みます。

## カスタムシステムプロンプト

AI のシステムプロンプトは、いくつかの方法でカスタマイズできます。

- **グローバルシステムプロンプト**: `~/.kimi/AGENTS.md` に記述します。すべてのプロジェクトに適用されます。
- **プロジェクト単位のシステムプロンプト**: プロジェクトルートの `AGENTS.md` に記述します。現在のプロジェクトにのみ適用されます。
- **起動パラメーター**: 起動時に `--system-prompt` フラグで指定します。

プロジェクト単位の設定はグローバル設定より優先され、起動パラメーターが最も高い優先度を持ちます。

## MCP 連携

Kimi Code CLI は Model Context Protocol (MCP) に対応しており、外部ツールやデータソースに接続して AI の機能を拡張できます。

- **MCP サーバー設定**: 設定ファイルに MCP サーバーのアドレスを追加すると、AI が外部ツールを呼び出せるようになります。
- **組み込み MCP サポート**: よく使われる一部の MCP ツールは組み込み済みで、追加設定は不要です。
- **カスタム MCP サーバー**: 独自の MCP サーバーを開発して、ドメイン固有の機能を提供できます。

MCP 設定は `~/.kimi/config.toml`、またはプロジェクト単位の設定ファイルに配置できます。

## 環境変数

Kimi Code CLI は環境変数による設定にも対応しており、CI/CD パイプラインやスクリプトで便利です。

| 環境変数 | 説明 |
| --- | --- |
| `KIMI_API_KEY` | API キー |
| `KIMI_BASE_URL` | カスタム API エンドポイント |
| `KIMI_MODEL` | デフォルトモデル名 |
| `KIMI_MAX_TOKENS` | 出力トークン数の上限 |

環境変数は、設定ファイル内の設定よりも優先されます。
