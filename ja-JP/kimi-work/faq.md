# Kimi Work よくある質問

## Kimi Work とWeb版の違いは何ですか？

Kimi のWebアプリは、ちょっとしたチャットや質問に最適です。一方、Kimi Work は深いワークフローのために設計されたローカル Agent です。ローカルフォルダの読み取りと処理、WebBridge を介したWebの自律的な操作、バックグラウンドでの Python コード実行、スケジュールされたタスクの実行ができます。いわば、システムレベルで働くデジタル社員です。

## Kimi Work はローカルファイルにアクセスする際、私のプライバシーをどう守りますか？

ファイルの扱いは、すべてあなたが管理できます。Kimi Work には権限管理が用意されており、次の方法で許可できます。

- **権限をリクエスト**: 操作前に許可を求めます — Kimi がローカルファイル内で変更、上書き、またはコードの実行を行う前に、明示的な許可を求めます。
- **すべて許可**: 許可を求めずに直接実行します。

「権限をリクエスト」を選んだ場合、あなたの同意なしに処理が進むことはありません。

## WebBridge（ブラウザ自動操作）では具体的に何ができますか？

WebBridge により、Kimi は人間のようにブラウザを使えるようになります。たとえば、Webサイトの最新ニュースを確認して要約したり、過去の株価データを取得してローカルの Excel に保存したりできます。クリック、スクロール、データ抽出を自律的に行うため、手作業にかかる時間を大幅に節約できます。

## スケジュールされたタスクでは何ができますか？コンピュータがスリープ中でも実行されますか？

スケジュールされたタスクを使うと、毎日、毎週、毎月、または1回限り（繰り返しなし）のスケジュールで、指定した時刻に Kimi が固定タスクを自動実行できます。日々のブリーフィング、週次モニタリング、定期的なクリーンアップに最適です。

Kimi Work デスクトップでは、スケジュールされたタスクは**ローカルで**実行され、**アプリが開いている間**にのみ実行されます。コンピュータがスリープ中またはシャットダウン中だったり、アプリが閉じていたりして実行できなかったトリガーは、次回アプリを開いたときに**さかのぼって実行されることはありません**。そのため、夜間にタスクを実行したい場合は、コンピュータと Kimi Work アプリを起動したままにしてください。（一方、Kimi で作成したタスクはクラウドで実行されるため、クライアントを開いたままにしておく必要はありません。）

詳しくは[スケジュールされたタスク](/features/scheduled-tasks)をご覧ください。
