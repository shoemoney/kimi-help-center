# クレジットの更新と利用ルール

<Callout type="info">
Kimiのメンバーシップ特典では、各機能（Agent 系列、Kimi Code など）が1つのクレジットプールを共有します。クレジットは実際の利用量に応じて消費されます。
</Callout>

## 共有クレジットプールの仕組み
機能ごとに個別のquotaが割り当てられるのではなく、メンバーシップでは1つのクレジットプールが提供されます。メンバーシップの各機能（Agent 系列、Kimi Code など）は、どこでも使える共通のクレジットプールを共有します。
| 機能 | 説明 |
|---------|-------------|
| **Agentタスク** | ウェブサイト、ドキュメント、スライド、スプレッドシート、Deep Research |
| **Kimi Claw** | クラウドにデプロイされた、あなた専用のAIアシスタント |
| **その他の機能** | 画像生成など |

> **Kimi Chat**: 最新モデルとの会話（quotaは消費されません）

<Callout type="tip">
つまり、共有プール内のcreditは自由に配分できます。ある月はリサーチに多めに、翌月はドキュメントに多めに使う、といった使い方が可能です。Kimi Chatはquotaを消費しません。
</Callout>

## クレジットはどのように計算されますか？
クレジットは、タスクで処理されるトークン数に基づいて消費されます。入力や出力が長いほど、より多くのトークンを使用します。

<Callout type="info">
**無料プラン利用者向けの目安**:
- シンプルなスライドデッキの生成 ≈ クレジットの1〜2%
- Deep Researchレポートの実行 ≈ 5〜10%
- コードスニペットの作成 ≈ 0.5〜2%
上位プランでは、クレジットプールも比例して大きくなります。
</Callout>

## クレジットの更新ルール
| ルール | 説明 |
|------|-------------|
| **サイクル** | 月額サブスクライバー、年額サブスクライバーのいずれも、**毎月**のサイクルでクレジットを受け取ります |
| **有効期限** | 未使用のクレジットは各サイクルの終了時に失効します。繰り越しや現金への換金はできません |
| **制限** | 個別のタスクには、UIに表示される5時間および7日間のconcurrency制限が適用される場合があります |

## クレジットを使い切った場合
- すでに進行中のタスクは通常どおり完了します
- 新しいタスクでは「クレジットが不足しています」というプロンプトが表示されます

**選択肢**:

- 次回の請求サイクルでクレジットが更新されるまで待つ
- 上位プランにアップグレードして、毎月の利用枠を増やす
## クレジットは具体的にいつ更新されますか？
1. **サイクル基準** — クレジットはカレンダー上の月初ではなく、サブスクリプションの契約応当日に更新されます
2. **繰り越しなし** — 残りのクレジットはゼロにリセットされ、その後、割り当て分が全額再付与されます
3. **例** — 12月1日午後3:00に登録した場合、クレジットは1月1日午後3:00に更新されます

<Callout type="info">
**システムエラー**: システム上の問題でタスクが失敗した場合は、👎ボタンから報告し、クレジットの返還をリクエストしてください。
</Callout>
