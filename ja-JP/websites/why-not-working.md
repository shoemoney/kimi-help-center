# なぜ動かないのですか？

<Callout type="tip">
フルスタックプロジェクトは、**フロントエンドUI、バックエンドサービス、永続ストレージ**で構成されます。Kimi Agent はそのすべてを生成できますが、正しく実行できるかどうかは、環境設定、認証設定、公開操作に左右されます。
</Callout>

アプリが期待どおりに動かない場合、たいていはバックエンド機能が不足しているわけではありません。多くの場合、プレビュー、認証、データベース、公開のいずれかの手順が完了していないことが原因です。

## フルスタックのワークフロー 

1. **生成**: Agent がフロントエンド + バックエンド + データベーススキーマとデータロジックを作成します。
2. **プレビュー**: ローカルのフルスタックテストのためにサンドボックスで実行します（一部のケースでは手動での起動が必要です）。
3. **バージョン管理**: Agent はバージョン管理ツールを使い、コミットを自動作成できます。
4. **ロールバック**: 以前の任意のコミットバージョンに戻せます。
5. **公開 / 共有**: 手動で公開した後にのみ、アプリが公開URLへデプロイされます。

## よくある失敗の原因 

| 症状 | 考えられる原因 | 対処方法 |
|----------|-------------|------------|
| フロントエンドは読み込まれるが API が失敗する | サンドボックスのランタイムが起動していない | サンドボックスを起動し、プレビューを再実行する |
| データが保存されない、または表示されない | DB が初期化またはマイグレーションされていない | DB セットアップまたはマイグレーション手順を再実行する |
| ログインに失敗する | 認証フローが正しく設定されていない | Kimi Login の設定とコールバック設定を確認する |
| 他の人がアプリにアクセスできない | アプリが公開されていない | **公開/共有**をクリックしてデプロイする |
| 最近の変更で機能が壊れた | 最新バージョンでリグレッションが発生している | 安定していたコミットへロールバックする |

## 認証サポート

- **フェーズ1**: **Kimi Login** に対応しています。
- **次のフェーズ**: 追加の OAuth プロバイダーに対応予定です。
- **あわせて対応**: 標準的な DB ベースのメールアドレス/パスワードによるアカウントログインも Agent で生成できます。

## バージョンとロールバック

- Agent は新しいバージョン管理ツールに対応しており、開発中に自律的に `git commit` を実行できます。
- 必要に応じてバージョン履歴を確認し、選択したコミットへロールバックできます。

## プレビューと公開

- **プレビュー**: サンドボックス内での開発・テスト用です。一部のシナリオでは、サンドボックスの手動起動が必要になる場合があります。
- **公開/共有**: ユーザーが手動で行う操作で、アプリを公開アクセス可能な環境へデプロイします。

## Agent が得意なこと

- フルスタックプロダクトの高速プロトタイピング
- 永続ストレージを使った CRUD フロー
- 基本的な管理画面やバックオフィス向けデータ操作
- ログイン、データ、デプロイフローを備えたエンドツーエンドのデモプロジェクト

## 現在の制約

- 高度な本番運用（たとえば、複雑な SRE やマルチリージョン HA）には、引き続き手作業でのエンジニアリングが必要です。
- リスクの高い本番シナリオでは、リリース前にセキュリティレビューとデプロイ環境の強化を行ってください。
