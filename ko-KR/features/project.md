# 프로젝트

프로젝트는 지속형 작업 공간입니다. 장기간 이어지는 하나의 작업에 필요한 참고 파일, 대화, 프로젝트 지침을 한 프로젝트 안에 모아둘 수 있으며, 프로젝트 안에서 시작하는 모든 대화에는 이 context가 자동으로 적용됩니다. 따라서 매번 같은 파일을 다시 업로드하거나 프로젝트 배경을 다시 설명할 필요가 없습니다.

**프로젝트를 사용하면 좋은 경우**: 시간이 지나도 계속 이어지는 작업이거나, 결과물이 여러 개 나오거나, 같은 파일 묶음에 의존하는 작업이라면 프로젝트를 만드세요. 예를 들어 문서 시리즈를 작성하거나, 지속적으로 리서치를 진행하거나, 코드베이스를 유지 관리할 때 적합합니다. 작업이 독립적이고 공유 context가 필요 없다면 일반 대화를 사용하면 됩니다.

<Callout type="info">
Kimi Work 데스크톱 앱에도 "프로젝트"가 있지만, 여기서 설명하는 Kimi(Chat) 프로젝트와는 별개입니다. 두 프로젝트는 서로 연결되어 있지 않으며 데이터를 공유하지 않습니다.
</Callout>

## 프로젝트 만들기 및 관리

**진입 경로**:
- 사이드바의 "프로젝트" 섹션 오른쪽에 있는 "+" 버튼;
- 홈 프로젝트 선택기 상단의 "+ 새 프로젝트" 항목.

**만들기**: 프로젝트 이름(필수, 1~50자)을 입력하고 필요하면 프로젝트 지침을 추가한 뒤, "생성"을 클릭해 프로젝트 홈 페이지를 엽니다.

**편집 / 삭제**:
- 사이드바에서 프로젝트 이름에 마우스를 올리거나 오른쪽 클릭해 "제목 편집" 또는 "고정"을 선택합니다;
- 프로젝트를 삭제하려면 확인이 필요합니다. **삭제하면 해당 프로젝트의 대화, 파일, 프로젝트 지침이 영구적으로 제거되며 복구할 수 없습니다**. 신중하게 진행하세요.

**사이드바**: "프로젝트" 섹션은 Kimi Claw 항목 아래, 대화 기록 위에 위치하며, 최근 생성된 순서대로 프로젝트를 표시합니다. 프로젝트를 펼치면 그 안의 대화를 볼 수 있습니다.

## 프로젝트 홈 페이지

프로젝트 홈 페이지는 3열 레이아웃으로 구성됩니다:
- **왼쪽**: 표준 사이드바;
- **가운데**: 대화 시작 영역과 프로젝트의 대화 목록. 입력 상자에는 "'project name'에서 대화 시작…"이 표시되며, 여기에서 메시지를 보내면 현재 프로젝트에 자동으로 속하는 대화가 생성됩니다;
- **오른쪽 패널**: 지침과 파일, 두 블록으로 구성됩니다(접기 가능).

## 프로젝트 대화에서 할 수 있는 일

프로젝트 안의 대화는 일반 Kimi 대화와 같은 기능을 제공하면서도, 프로젝트 context를 자동으로 포함합니다. 다음을 사용할 수 있습니다:
- **프로젝트 파일**(모델이 필요할 때 읽음)과 **프로젝트 지침**;
- **플러그인, Skills, Goal**;
- **모델 선택**.

결과물이 서로 다르다면 각각 별도의 대화를 시작해 메시지와 결과가 한 주제에 집중되도록 하세요. 프로젝트는 이렇게 관련된 대화들을 한곳에 모아둡니다.

## 프로젝트 지침

- 프로젝트 지침은 해당 프로젝트에만 적용되는 사용자 지정 지침(일반 텍스트)이며, Kimi는 프로젝트 내 모든 대화에서 이를 따릅니다;
- 예: "당신은 시니어 제품 관리자입니다. 중국어로 답하고 Markdown 형식으로 출력하세요.";
- 저장한 뒤 다음 메시지부터, 또는 새 대화부터 적용됩니다.

## 프로젝트 파일

- 프로젝트에 참고 파일을 업로드하면 해당 프로젝트의 모든 대화에서 사용할 수 있습니다;
- 지원 형식은 Kimi Agent 업로드와 동일합니다: PDF, DOCX, XLSX, CSV, TXT, MD, 일반적인 코드 파일, 일반적인 이미지 형식;
- **각 파일은 100 MB 이하여야 하며, 최대 50개까지 업로드할 수 있습니다**;
- 프로젝트 파일은 **모델이 필요할 때 읽습니다**. 매 turn마다 모든 파일의 전체 텍스트를 미리 불러오는 대신, 모델이 질문을 바탕으로 필요한 파일을 판단합니다;
- 파일 블록 하단에는 용량 막대가 표시됩니다. 한도에 가까워지거나 한도에 도달하면 파일 삭제 또는 플랜 업그레이드 안내가 표시됩니다.

## 프로젝트에서 context가 작동하는 방식

프로젝트에서 대화를 시작하면 모델에 주입되는 context에는 **system prompt + 전역 메인 memory + 프로젝트 지침 + 필요할 때 읽는 프로젝트 파일**이 포함됩니다.

일반(비프로젝트) 대화에는 프로젝트 지침이나 파일이 주입되지 않습니다. 프로젝트의 지침과 파일은 해당 프로젝트 안에서만 적용되며, 다른 프로젝트나 일반 대화에는 영향을 주지 않습니다.

## quota 및 플랜

프로젝트 수와 프로젝트 저장 공간은 멤버십 플랜에 따라 달라집니다:

| 플랜 | Free | Go | Pro | Max | Ultra |
|---|---|---|---|---|---|
| 프로젝트 | 2 | 20 | 20 | 100 | 100 |
| 프로젝트 저장 공간 | 500MB | 20GB | 20GB | 50GB | 50GB |

기타 한도(예: 프로젝트당 대화 수, 프로젝트 지침의 글자 수 제한)도 플랜에 따라 달라집니다. 최신 수치는 [멤버십 플랜 페이지](/membership/membership-pricing)를 참고하세요.

## FAQ

### 프로젝트 파일은 대화의 모든 turn마다 전체를 읽나요?
아니요. 프로젝트 파일은 필요할 때만 읽습니다. 매 turn마다 모든 파일을 미리 불러오는 것이 아니라, 모델이 질문을 바탕으로 필요한 파일을 판단하고 해당 파일만 읽습니다.

### 프로젝트 하나에 파일을 몇 개까지 보관할 수 있나요?
각 파일은 100 MB 이하여야 하며, 최대 50개까지 업로드할 수 있습니다. 전체 프로젝트 저장 공간은 플랜에 따라 달라집니다. [멤버십 플랜 페이지](/membership/membership-pricing)를 참고하세요.

### 프로젝트를 삭제하면 어떻게 되나요?
프로젝트를 삭제하면 해당 프로젝트의 대화, 파일, 프로젝트 지침이 **영구적으로 제거**되며 되돌릴 수 없습니다. 삭제 전에 반드시 확인하세요.

### 프로젝트 수 또는 저장 공간 한도에 도달하면 어떻게 하나요?
더 이상 필요하지 않은 프로젝트나 파일을 삭제해 공간을 확보하거나, 더 높은 quota가 제공되는 플랜으로 업그레이드하세요. 자세한 내용은 [멤버십 플랜 페이지](/membership/membership-pricing)를 참고하세요.
