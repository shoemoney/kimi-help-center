# VS Code 핵심 작업

<Callout type="warning">
**VS Code 확장 적응 작업 진행 중**

현재 VS Code용 Kimi Code는 기존 Python CLI 사용자에게만 신규 설치가 열려 있습니다. 이미 확장을 설치한 기존 사용자는 새 CLI로 업그레이드한 뒤에도 계속 사용할 수 있습니다. TS 버전 CLI를 사용하는 다른 사용자는 현재 설치가 지원되지 않습니다.
</Callout>

## 패널 열기

Activity Bar에서 Kimi 아이콘을 클릭하거나 Command Palette에서 "Kimi Code" 명령을 실행하세요.

## 입력 및 컨트롤

### 파일 참조

`@`를 입력한 뒤 파일 또는 폴더 이름을 선택하세요. 예를 들어 폴더를 참조하려면 `@src/handlers/`, 파일을 참조하려면 `@app.ts`, 특정 줄 범위를 참조하려면 `@src/app.ts:10-20`을 사용합니다.

`Alt+K`를 누르면 현재 파일이나 선택한 코드를 참조로 빠르게 삽입할 수 있습니다.

### 슬래시 명령

`/`를 입력해 명령 메뉴를 엽니다. `/init`으로 프로젝트를 스캔하고 문서를 생성하거나, `/compact`로 지나치게 긴 컨텍스트를 압축할 수 있습니다.

### 입력 기록

입력 상자에서 `↑` / `↓`를 누르면 최근에 보낸 메시지를 빠르게 훑어볼 수 있어 질문을 반복하거나 수정하기가 더 쉽습니다.

### 미디어 파일 입력

미디어 파일을 붙여넣거나, 끌어다 놓거나, 직접 선택할 수 있습니다. 지원 형식에는 PNG, JPEG, GIF, WebP, HEIC 같은 이미지 형식과 MP4, WebM, MOV 같은 동영상 형식이 포함됩니다.

- **붙여넣기 / 끌어다 놓기**: 이미지 1개의 원본 크기는 최대 5MB까지 가능합니다. 시스템이 자동으로 압축하며, HEIC를 JPEG로 변환하고, 너무 큰 이미지는 크기를 조정하며, 품질을 낮춰 약 2MB로 줄이는 작업이 포함됩니다.
- **파일 선택기**: 입력 상자의 "+" 버튼이나 `@` 메뉴를 통해 파일을 선택할 때 이미지는 최대 10MB, 동영상은 최대 20MB까지 지원됩니다.
- **일반 제한**: 메시지마다 최대 9개 파일을 첨부할 수 있으며, 총 크기는 최대 80MB입니다. 미디어 파일이 첨부되면 멀티모달 입력을 지원하지 않는 모델은 자동으로 제외됩니다.

### 메시지 대기열

Kimi가 응답하는 동안에도 입력 상자에 계속 메시지를 입력하고 보낼 수 있습니다. 이러한 메시지는 사라지지 않고 **메시지 대기열**에 추가됩니다. 하단 도구 모음에는 대기열 개수가 표시되며, 이를 클릭하면 대기열 패널을 펼칠 수 있습니다.

- 전송 대기 중인 메시지 목록 보기
- 대기열의 메시지 편집 또는 삭제
- 메시지 순서 변경
- Kimi가 응답하는 동안 대기열 항목의 ⚡ 아이콘을 클릭하면 해당 메시지를 즉시 **방향 조정 지시**로 삽입하여 Kimi가 현재 응답의 방향을 조정하도록 안내할 수 있습니다.

### 모델 및 Thinking mode

입력 바의 드롭다운 메뉴에서 모델을 전환합니다.

일부 모델은 확장된 추론 기능을 지원합니다. Thinking mode 토글에는 세 가지 상태가 있습니다. 모델이 Thinking mode를 지원하지 않으면 숨겨지고, 사용자가 수동으로 켜거나 끌 수 있으며, k2-thinking 같은 모델에서는 항상 켜진 상태로 유지됩니다.

활성화한 뒤에는 응답에서 사고 단계가 기본적으로 접혀 표시됩니다. 이를 펼쳐 추론 과정을 확인할 수 있습니다. 설정에서 `kimi.alwaysExpandThinking`을 활성화하면 사고 과정을 기본적으로 펼쳐 표시합니다.

## 작업 모드

### 작업 확인 및 도구 실행

Kimi가 도구 실행이나 파일 쓰기를 제안하면 세 가지 옵션이 있는 확인 대화상자가 나타납니다.

- **예**: 현재 작업만 승인
- **예, 이 세션 동안**: 새 세션이 시작될 때까지 현재 세션에서 유사한 작업 승인
- **아니요**: 작업 실행 거부

모든 도구 호출을 자동 승인하려면 설정에서 `kimi.yoloMode`를 활성화하세요. 워크플로를 신뢰하며 더 높은 효율이 필요할 때 적합합니다.

### 질문 대화상자

실행 중 Kimi가 구현 방식 선택처럼 사용자에게 질문할 수 있습니다. 하단에 질문 카드가 표시됩니다. 미리 설정된 옵션을 바로 선택하거나 "사용자 지정 응답..."을 선택해 직접 답변을 입력할 수 있습니다. 답변을 마치면 Kimi가 실행을 계속합니다.

### 계획 모드

입력 상자 왼쪽의 📋 아이콘을 클릭하면 계획 모드로 들어갑니다. 활성화하면 Kimi가 본격적으로 실행하기 전에 펼칠 수 있는 계획 카드를 먼저 출력하고, 수행하려는 단계를 나열합니다. 계속 진행하게 하기 전에 계획을 검토할 수 있습니다.

- 계획 모드 버튼은 새 세션마다 이전 설정을 유지합니다.
- Kimi가 이미 응답을 스트리밍 중인 경우, 현재 작업이 중단되지 않도록 계획 모드를 종료할 때 한 번 더 확인해야 합니다.

### 파일 변경 추적

Kimi가 파일을 수정하면 모든 변경 사항이 추적되어 "파일 변경 사항" 섹션에 표시됩니다. 수정된 파일 목록과 상태(추가됨, 수정됨, 삭제됨 등), 추가 및 삭제된 줄 통계를 확인할 수 있습니다.

각 파일에 대해 VS Code의 기본 diff 보기에서 변경 사항을 확인하거나, 원래 상태로 복원하거나, 변경 사항을 유지해 추적 기록을 지울 수 있습니다. 일괄 작업도 지원되므로 모든 변경 사항을 한 번에 유지하거나 폐기할 수 있습니다. 기준 상태는 세션에서 파일이 처음 수정될 때 캡처되며, 되돌리기를 실행하면 해당 기준 버전으로 파일이 복원됩니다.

## 컨텍스트 관리

### 세션 기록

패널 상단의 기록 드롭다운 메뉴를 클릭하면 이전 세션을 탐색할 수 있습니다. 세션 데이터는 로컬에 저장되며 키워드 검색을 지원합니다. 오래된 세션을 삭제하거나 세션을 불러와 이전 대화를 이어갈 수 있습니다.

상태 표시줄에는 컨텍스트 사용률과 입출력 token 수가 표시됩니다. 컨텍스트 사용량이 많을 때는 `/compact` 명령으로 압축하세요.

### 작업 디렉터리 전환

입력 상자 오른쪽의 기어 아이콘(Action Menu) → **작업 디렉터리**를 클릭하면 현재 Workspace의 여러 하위 디렉터리 사이에서 작업 디렉터리를 전환할 수 있습니다. 전환 후에는 Kimi가 새 디렉터리 컨텍스트를 기반으로 작업할 수 있도록 새 세션이 자동으로 시작됩니다. 등록된 하위 디렉터리를 바로 선택하거나 "찾아보기..."를 사용해 원하는 하위 폴더를 탐색할 수 있습니다.

## 작업 메뉴

### 기능 목록

입력 상자 오른쪽의 기어 아이콘을 클릭하면 작업 메뉴가 열리며, 다음 기능이 포함됩니다.

- **작업 디렉터리**: 현재 작업 디렉터리 전환(위의 "작업 디렉터리 전환" 참고)
- **MCP 서버**: MCP 서버 구성 패널 열기
- **일반 설정**: VS Code 설정에서 Kimi 구성 페이지 열기
- **로그 표시**: 문제 해결을 위해 Kimi Code 출력 로그 패널 열기
- **Kimi 재설정**: Kimi Webview를 재설정합니다. 인터페이스가 멈추거나 응답하지 않을 때 유용합니다.
- **로그아웃 / 로그인**: Kimi 계정에서 로그아웃하거나 다시 로그인

VS Code Command Palette에서 "Kimi Code: Run CLI"를 실행해 통합 터미널에서 Kimi Code CLI를 바로 시작할 수도 있습니다.
