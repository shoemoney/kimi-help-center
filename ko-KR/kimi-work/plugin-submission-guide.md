# 플러그인 생성 및 제출

제품이나 서비스를 Kimi에 연결하여 사용자가 대화 중에 해당 기능을 이용할 수 있도록 하려면, 이 가이드를 따라 공식 Kimi 플러그인 마켓플레이스에 등록할 플러그인을 생성, 테스트, 제출하세요.

## Kimi 플러그인이란?

Kimi 플러그인은 제품을 Kimi에 연결합니다. Kimi가 사용자의 제품이 유용한 시점을 이해하고, 사용자를 돕기 위해 필요한 워크플로우나 도구를 제공할 수 있도록 합니다. 플러그인은 다음을 포함할 수 있습니다:

- **스킬만**: 제품이나 사용 사례에 맞춰 재사용 가능한 워크플로우
- **MCP만**: MCP 서버를 통해 Kimi에 노출되는 도구 및 서비스
- **스킬과 MCP**: 제품 도구와 이를 효과적으로 사용할 수 있는 워크플로우의 결합

## 시작하기 전에

먼저 <a href="https://www.kimi.com/products/kimi-work">Kimi Work를 다운로드하여 설치</a>하세요. 다음을 준비하세요:

- 플러그인 이름, 설명, 로고
- 사용자가 자연어로 완료할 수 있어야 하는 핵심 작업
- 적용 가능한 경우 MCP 서버 URL

<Callout type="warning">
플러그인 로고에 타사 제품, 브랜드 또는 상표가 포함된 경우, 관련 권리 보유자에게 연락하여 제출 전 필요한 서면 승인을 받으세요.
</Callout>

## 1단계: 플러그인 생성 및 테스트

1. Kimi Work를 열고 대화창에 "/"를 입력한 후 **Plugin Builder**를 선택하세요.
2. 플러그인을 설명하고 준비한 정보를 제공하세요. 이미 Codex, Claude 또는 다른 플랫폼의 플러그인이 있는 경우, 해당 파일이나 프로젝트 URL을 제공하고 변환 지침을 따르세요.

3. **Plugins** → **Personal**로 이동하여 플러그인을 찾아 설치하세요.

4. 일반적인 경우와 예외 사례를 포함해 새로운 대화에서 핵심 기능을 테스트하세요. 대표적인 테스트 프롬프트를 최소 3개 이상 보관하세요.
5. Plugin Builder의 지침에 따라 완전한 플러그인 ZIP 파일을 얻으세요.

MCP 기반 플러그인의 경우 인증 흐름도 테스트하세요:

- **인증 없음**: 사용자는 설치 직후 플러그인을 사용할 수 있습니다.
- **OAuth**: 첫 설치 시 타사 인증 페이지가 열려야 합니다.
- **CLI 인증**: 설치 시 인증이 시작되지 않습니다. 사용자가 처음 플러그인을 호출할 때 대화에서 인증을 완료합니다. 성공적인 인증 후 일반적으로 다른 대화에서 다시 인증할 필요가 없습니다.

## 2단계: 신청서 제출

플러그인을 생성하고 테스트한 후 [Kimi 플러그인 제출 양식](https://moonshot.feishu.cn/share/base/form/shrcnZcnxlNJlbw845KoVgjEhkh)을 작성하고 플러그인 ZIP 파일을 업로드하세요.

양식에는 다음이 요구됩니다:

| 항목 | 요구 사항 |
| --- | --- |
| 플러그인 이름, 설명 및 ZIP 파일 | 필수 |
| 플러그인 유형 | 스킬만, MCP만, 또는 하이브리드 |
| MCP 인증 | MCP 전용 및 하이브리드 플러그인 필수 |
| 대상 지역 | 중국 본토, 해외, 또는 둘 다 |
| 하이라이트 및 권장 테스트 프롬프트 | 최소 3개의 테스트 프롬프트 |
| 공동 마케팅 관심 및 자료 | 자료는 선택 사항이며 공동 마케팅 논의를 원할 경우만 필요 |
| 승인 및 규정 준수 상태 | 추가 논의가 필요한 사항 공개 |
| 연락 이메일 | 검토 업데이트 및 추가 정보 요청 시 사용 |
| 회사 또는 팀, 관련 웹사이트 및 참고 사항 | 선택 사항 |

<Callout type="warning">
양식이나 플러그인 ZIP에 비밀번호, 토큰, API 키, 개인 키 또는 기타 비밀을 포함하지 마세요. 사용자가 자신의 키가 필요한 경우, 획득 및 설정 방법만 설명하세요.
</Callout>

## 다음 단계

Kimi 팀이 신청서와 플러그인 ZIP을 검토합니다. 플러그인이 검토를 통과하거나 추가 정보나 변경이 필요한 경우, 제공한 이메일 주소로 연락하여 다음 단계를 공유할 것입니다.

## FAQ

### MCP 서버 없이 플러그인을 제출할 수 있나요?

네. 스킬 전용 플러그인도 지원됩니다. 플러그인 유형으로 **스킬만**을 선택하세요.

### Codex, Claude 또는 다른 플랫폼의 플러그인을 제출할 수 있나요?

네. 1단계에서 기존 플러그인 파일이나 프로젝트 URL을 Plugin Builder에 제공하고 변환 지침을 따르세요. 변환된 플러그인을 Kimi Work에서 설치하고 테스트한 후 생성된 ZIP 파일을 제출하세요.

### 어떤 MCP 인증 방법이 지원되나요?

현재 다음 세 가지 방법이 지원됩니다:

- **인증 없음**: 사용자는 설치 직후 로그인이나 기타 신원 확인 없이 플러그인을 사용할 수 있습니다.
- **OAuth**: 사용자가 플러그인을 처음 설치할 때 타사 제품의 인증 페이지로 자동 리디렉션됩니다. 인증 후 플러그인을 사용할 수 있습니다.
- **CLI 인증**: 설치 시 인증 흐름이 시작되지 않습니다. 사용자가 대화에서 처음 플러그인을 호출할 때 대화에 표시된 지침으로 인증을 완료합니다. 성공적인 인증 후 일반적으로 다른 대화에서 다시 인증할 필요가 없습니다.

플러그인의 실제 인증 방법과 일치하는 흐름을 테스트하세요. OAuth 플러그인이 첫 설치 시 리디렉션되지 않거나, CLI 인증 플러그인이 반복적으로 사용자에게 인증을 요구하는 경우, 신청서 제출 전 MCP 서버의 인증 구성을 확인하고 **추가 참고 사항**에 문제를 설명하세요.

### OAuth 인증 흐름은 어떻게 되나요?

OAuth가 활성화된 MCP 서버의 경우, Plugin Builder는 MCP 서버 URL에서 관련 인증 정보를 식별합니다. 플러그인 생성 후 사용자가 처음 설치할 때 타사 제품의 인증 페이지로 이동됩니다.

### Kimi와 더 광범위한 파트너십을 탐색하고 싶다면 어떻게 해야 하나요?

먼저 이 가이드의 플러그인 생성, 테스트 및 제출 프로세스를 완료하세요. 플러그인 등록 외에 다른 형태의 협업을 탐색하고 싶다면, **추가 참고 사항**에 제안을 간략히 설명하세요. Kimi 팀이 상황에 따라 연락할 수 있습니다.

### 신청서 제출이 등록을 보장하나요?

아니요. Kimi 팀은 플러그인의 기능, 사용자 경험, 보안, 서비스 안정성 및 관련 승인 상태를 평가합니다.
