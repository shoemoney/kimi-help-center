# Kimi Websites FAQ

> 미리보기 패널 버튼, 편집 모드, 게시 및 게시 취소에 대한 전체 안내는 [Kimi Websites](/websites/websites-overview)를 참고하세요. 이 페이지에서는 자주 발생하는 문제 해결 방법만 다룹니다.

## 미리보기가 로드되지 않거나 최신 버전이 보이지 않나요?

> 예: "웹사이트가 표시되지 않아요", "미리보기가 여전히 이전 버전이에요", "최신 저장 버전이 보이지 않아요" 등.

대부분의 경우 웹사이트는 정상적으로 생성되고 저장되어 있습니다. "보이지 않는" 문제는 보통 미리보기 패널이나 버전 카드 표시에서 발생합니다. 가장 흔한 원인은 잘못된 프로젝트 디렉터리입니다. 그 밖의 경우에는 아래 순서대로 확인하세요.

<Callout type="warning">
**프로젝트 디렉터리를 확인하세요**: 웹사이트 프로젝트는 반드시 `/mnt/agents/output/app`에 있어야 합니다. 미리보기는 이 디렉터리에서 저장된 버전만 읽습니다. Kimi가 프로젝트를 다른 위치(예: 임시 `/tmp` 디렉터리)에 둔 경우, 버전 저장은 성공하더라도 미리보기에서 읽을 수 없습니다. Kimi에게 프로젝트를 이 디렉터리로 옮긴 뒤 다시 저장해 달라고 요청하세요.
</Callout>

1. **페이지를 새로고침하거나 대화를 다시 여세요**—버전 카드가 표시되기까지 몇 초가 걸릴 수 있습니다.
2. **대화에서 Kimi에게 새 버전을 저장해 달라고 요청하세요.**
3. **대화가 매우 길다면 새 대화를 시작해 보세요**(아래의 "대화가 너무 긴데 새로 시작해야 하나요?"를 참고하세요).
4. 그래도 표시되지 않는다면: 보통 코드와 버전은 정상적으로 저장되어 있습니다(Kimi에게 버전 번호를 물어볼 수 있습니다). 이는 일시적인 미리보기 서비스 변동인 경우가 많으니 나중에 다시 시도해 주세요. 문제가 계속되면 미리보기 패널의 **사용자 피드백**(봉투 아이콘)을 클릭해 버전 번호와 함께 피드백을 제출해 주세요. 담당 팀이 확인하겠습니다.

## 웹사이트가 빈 화면이거나, 흰 화면이거나, 충돌하거나, 반응하지 않나요?

> 예: "페이지가 완전히 비어 있어요", "웹사이트에 아무것도 없어요", "웹사이트가 충돌했어요", "아무것도 표시되지 않거나 클릭해도 반응이 없어요" 등.

- 빈 화면이나 충돌은 보통 **프런트엔드 런타임 오류** 때문에 발생합니다(예: 누락된 의존성, 하위 페이지 직접 접근, 특정 리소스나 이미지 로드 실패). 대화에서 증상을 Kimi에게 설명하세요(스크린샷이 있으면 도움이 됩니다). Kimi가 문제를 찾아 수정한 뒤 새 버전을 저장합니다.
- **파일 누락**으로 인해 빈 화면이 발생한 것 같다면, 웹사이트의 각 버전에는 스냅샷이 저장되어 있습니다. Kimi에게 이전 버전에서 복원해 달라고 요청하세요(아래의 "프로젝트 파일이나 디렉터리가 사라졌어요" 참고).
- **브라우저 호환성**: 일부 개인정보 보호 중심 브라우저(Brave, 특정 Firefox 부가 기능)는 프런트엔드 리소스 로딩을 차단해 표시 이상을 일으킬 수 있습니다. Kimi 도메인을 허용 목록에 추가하거나, 보호/개인정보 차단 기능을 일시적으로 끄거나, Chrome / Edge / Safari로 전환해 보세요.

## "게시"를 클릭했는데 실패하면 어떻게 하나요?

처리 방법은 위와 같습니다. 나중에 다시 시도해 주세요. 문제가 계속되면 버전 번호와 함께 **사용자 피드백**으로 제출해 주세요. 버전은 이미 정상적으로 저장되어 있으므로 처음부터 다시 빌드할 필요는 없습니다.

## 웹사이트 링크는 얼마나 오래 유효한가요? 만료되나요?

**게시**를 클릭해 웹사이트를 공개 배포하면, 직접 **게시 취소**를 클릭해 사이트를 비공개로 전환하거나 콘텐츠가 부적절한 내용으로 표시되지 않는 한 생성된 링크는 무기한 유효합니다.

## 콘텐츠, 데이터, 기록이 사라졌나요?

> 예: "홈페이지의 콘텐츠가 사라졌어요", "데이터베이스에 업로드한 지식이 없어졌어요", "업로드한 정보가 보이지 않아요", "AI가 데이터가 영구적으로 손실됐다고 해요" 등.

대부분의 경우 데이터가 실제로 손실된 것은 아닙니다. 아래 순서대로 확인하세요.

1. **먼저 웹사이트가 실제로 "풀스택"인지 확인하세요**: **백엔드(데이터베이스) 기능**으로 구축된 풀스택 웹사이트만 플랫폼의 클라우드 데이터베이스에 데이터를 저장하며, 방문이나 기기 변경 후에도 데이터가 유지됩니다. 실제로는 "풀스택"이라고 했던 많은 웹사이트가 **결과적으로 프런트엔드 전용**인 경우가 많고, 이때 데이터는 데이터베이스에 전혀 들어가지 않습니다. 이 경우 새로고침하거나 기기를 바꾸면 이전 데이터가 사라지는 것이 자연스럽습니다. Kimi에게 프로젝트에 실제 백엔드와 데이터베이스가 포함되어 있는지 확인해 달라고 하세요.
2. **순수 프런트엔드 웹사이트**: 데이터는 현재 브라우저의 로컬 저장소(localStorage)에만 저장됩니다. 브라우저/기기를 바꾸거나 브라우저 데이터를 삭제하면 데이터가 사라집니다. 장기간, 여러 기기에서 데이터를 유지해야 한다면 Kimi에게 데이터베이스를 사용하는 풀스택 솔루션으로 전환해 달라고 요청하세요.
3. **풀스택 웹사이트로 확인된 경우**: 데이터는 플랫폼이 관리하는 클라우드 데이터베이스에 저장됩니다. **새 버전을 게시해도 기존 데이터는 삭제되지 않습니다**. 풀스택인데도 데이터가 보이지 않는다면 보통 일시적인 문제이므로 새로고침하거나 나중에 다시 시도하세요.
4. **데이터가 실제로 손실된 것이 확인된 경우**: 미리보기 패널의 **사용자 피드백**(봉투 아이콘)을 클릭해 피드백을 제출해 주세요. 담당 팀이 확인하겠습니다. 덮어쓰기를 방지하기 위해 이 시점에서는 반복 작업을 계속하지 마세요.

## 프로젝트 파일이나 디렉터리가 사라졌거나, "환경 초기화" / "복구할 수 없음" 메시지가 표시되나요?

> 예: "웹사이트 프로젝트 디렉터리가 사라졌고 복구할 수 없어요", "파일이 없어졌어요", "환경 초기화 메시지가 떠요" 등.

- 웹사이트의 각 버전은 **스냅샷을 저장**하므로, 보통 이전 버전에서 소스 코드를 복구할 수 있습니다. Kimi에게 이전 버전 목록을 보여 달라고 하고, 특정 버전으로 롤백/복원해 달라고 요청하세요.
- 이 문제가 **매우 긴 대화**에서 발생했다면(특히 대화 중간에 모델을 전환한 경우), 새 대화를 시작하는 것을 권장합니다(다음 항목 참고).
- 그래도 복구할 수 없다면 **사용자 피드백**을 클릭해 피드백을 제출해 주세요. 담당 팀이 확인하겠습니다.

## 대화가 너무 긴데 새로 시작해야 하나요?

대화가 오랫동안 이어져 여러 버전에 걸쳐 있거나, 대화 중간에 모델을 전환한 경우(예: K2.6 → K3), 현재 기능이 최신 버전이 아닐 수 있어 컨텍스트 손실이나 파일 이상이 발생할 수 있습니다. 최신 구축 및 제공 기능을 사용하려면 **새 대화를 시작하는 것을 권장합니다**. 이미 게시된 웹사이트와 이전 버전에는 영향이 없으며 정상적으로 접근할 수 있습니다.

## 코드를 내보낸 뒤 직접 배포할 수 있나요?

전체 프로젝트 코드를 다운로드해 자체 서버에 배포할 수 있습니다. 다만 아래 두 가지는 Kimi 플랫폼에서 제공하는 기능이므로 **코드와 함께 이전되지 않습니다**.

- **Kimi 계정 로그인**: 플랫폼이 제공하는 로그인 기능이므로 Kimi 플랫폼을 벗어나면 그대로 사용할 수 없습니다. 자체 배포에서 로그인이 필요하다면 Kimi에게 자체 데이터베이스 기반의 사용자명/비밀번호 로그인 시스템을 구현해 달라고 요청하세요.
- **플랫폼 관리 데이터베이스**: 풀스택 웹사이트 데이터는 해당 사이트에 플랫폼이 할당한 클라우드 데이터베이스에 저장됩니다. 내보낸 코드에는 이 데이터가 포함되지 않으며, 사용자의 자체 데이터베이스에 자동으로 연결되지도 않습니다. 직접 배포하려면 자체 데이터베이스를 설정하고 데이터를 마이그레이션해야 합니다.

웹페이지를 공개로 접근 가능하게 만드는 것이 목적이라면, 플랫폼의 **공유 → 게시** 기능을 사용하면 됩니다. 자체 서버를 설정할 필요가 없으며 Kimi 계정 로그인과 클라우드 데이터도 계속 정상적으로 작동합니다.

## 생성된 웹사이트가 요구사항과 맞지 않나요?

- 대화에서 무엇이 맞지 않는지 구체적으로 알려 주세요. 예: 색상, 레이아웃, 문구, 기능 모듈, 데이터 표 등.
- 참고 이미지, 예시 웹페이지, 더 자세한 텍스트 설명을 업로드하면 Agent가 참고 자료에 맞춰 수정할 수 있습니다.
- 여러 차례 수정한 뒤에도 만족스럽지 않다면, 요구사항을 더 구조적으로 정리해 새 대화를 시작해 보세요.

## 생성 후에도 웹사이트 콘텐츠, 링크, 스타일을 수정할 수 있나요?

네. 원래 대화에서 Agent에게 수정하고 싶은 내용을 계속 알려 주세요. 예를 들면:

- "홈페이지 제목을 XXX로 바꿔줘"
- "'문의하기' 버튼 링크를 https://xxx 로 바꿔줘"
- "전체적으로 다크 테마로 바꿔줘"

수정이 끝나면 Agent가 새 링크를 다시 생성하고 배포합니다.

## 웹사이트에 백엔드, 데이터베이스, 로그인 기능을 추가하려면 어떻게 하나요?

- 웹사이트 제작 지시에서 데이터베이스와 로그인 기능이 있는 풀스택 웹페이지를 원한다고 명확히 강조하세요.
- 또는 Agent에게 먼저 프런트엔드 페이지를 생성하게 한 뒤, 소스 코드를 내보내 개발자에게 전달해 추가 개발을 맡길 수도 있습니다.

## 웹사이트 소스 코드를 다운로드하거나 GitHub로 내보낼 수 있나요?

현재 버전은 모든 파일을 로컬로 다운로드하는 기능을 지원합니다. 대화에서 "모든 파일"을 열고 다운로드 버튼을 클릭하세요.

## 웹사이트 생성/수정에는 credit이 얼마나 소모되나요?

웹사이트 생성은 복잡한 작업이므로 보통 상당한 양의 token/credit이 소모됩니다. 소모량은 다음에 따라 달라집니다.

- 페이지 수와 복잡도
- 이미지, 표, 상호작용 로직 포함 여부
- 반복 수정 횟수

시행착오를 줄이려면 요구사항을 최대한 명확하게 작성하는 것이 좋습니다. 결과가 만족스럽지 않다면 피드백으로 상황을 설명해 주세요.

## 웹사이트 생성이 매우 느리거나, 계속 대기열에 머물거나, 터미널이 실패하나요?

- 피크 시간대(평일 낮과 저녁)에는 대기열이 발생할 수 있습니다. 가급적 한산한 시간대에 이용하는 것을 권장합니다.
- 작업이 10분 넘게 멈춰 있다면 먼저 웹페이지를 새로고침해 보세요.
- 복잡한 웹사이트는 작업을 더 작은 단위로 나누는 것이 좋습니다. 홈페이지부터 시작한 뒤 하위 페이지와 기능을 점진적으로 추가하세요.

## Kimi Websites는 어떤 용도에 적합하고, 어떤 용도에는 적합하지 않나요?

**적합한 용도:**

- 개인 홈페이지/포트폴리오, 이벤트 랜딩 페이지, 제품 소개 페이지, 간단한 도구 페이지, 소규모 게임 프로토타입
- 디자인 아이디어를 빠르게 검증하고 인터랙티브 데모 생성
- 간단한 백엔드 데이터베이스와 사용자 시스템이 필요한 웹사이트

**적합하지 않은 용도:**

- 결제 시스템이 포함된 복잡한 웹사이트
- 높은 concurrency와 고가용성이 필요한 정식 프로덕션 환경
- 커스텀 도메인으로 장기간 안정적인 호스팅이 필요한 비즈니스 사이트
