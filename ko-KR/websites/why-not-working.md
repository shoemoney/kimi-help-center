# 작동하지 않는 이유

<Callout type="tip">
풀스택 프로젝트는 **프런트엔드 UI, 백엔드 서비스, 영구 저장소**로 구성됩니다. Kimi Agent는 이 세 가지를 모두 생성할 수 있지만, 실제 실행이 성공하려면 환경 설정, 인증 구성, 게시 작업이 제대로 이루어져야 합니다.
</Callout>

앱이 기대대로 작동하지 않는다면, 그 원인은 대개 백엔드 기능이 빠져서가 아닙니다. 보통은 미리보기, 인증, 데이터베이스, 게시 단계 중 하나가 마무리되지 않았기 때문입니다.

## 풀스택 워크플로

1. **생성**: 에이전트가 프런트엔드 + 백엔드 + 데이터베이스 스키마와 데이터 로직을 만듭니다.
2. **미리보기**: 샌드박스에서 실행해 로컬 풀스택 테스트를 진행합니다(경우에 따라 수동 시작이 필요할 수 있습니다).
3. **버전 관리**: 에이전트가 버전 관리 도구를 사용해 커밋을 자동으로 생성할 수 있습니다.
4. **롤백**: 이전 커밋 버전 중 원하는 시점으로 되돌릴 수 있습니다.
5. **게시 / 공유**: 직접 게시한 뒤에야 앱이 공개 URL로 배포됩니다.

## 흔한 실패 원인

| 증상 | 예상 원인 | 해결 방법 |
|----------|-------------|------------|
| 프런트엔드는 로드되지만 API가 실패함 | 샌드박스 런타임이 시작되지 않음 | 샌드박스를 시작하고 미리보기를 다시 실행하세요 |
| 데이터가 저장되지 않거나 보이지 않음 | DB가 초기화 또는 마이그레이션되지 않음 | DB 설정 또는 마이그레이션 단계를 다시 실행하세요 |
| 로그인이 실패함 | 인증 흐름이 올바르게 구성되지 않음 | Kimi Login 구성과 콜백 설정을 확인하세요 |
| 다른 사람이 앱에 접근할 수 없음 | 앱이 게시되지 않음 | **게시/공유**를 클릭해 배포하세요 |
| 최근 변경으로 기능이 망가짐 | 최신 버전에서 발생한 회귀 | 안정적인 커밋으로 롤백하세요 |

## 인증 지원

- **1단계**: **Kimi Login**을 지원합니다.
- **다음 단계**: 추가 OAuth 제공업체가 추가될 예정입니다.
- **추가 지원**: 표준 DB 기반 이메일/비밀번호 계정 로그인을 에이전트가 생성할 수 있습니다.

## 버전 관리와 롤백

- 에이전트는 새로운 버전 관리 도구를 지원하며, 개발 중 자율적으로 `git commit`을 수행할 수 있습니다.
- 버전 기록을 확인하고 필요할 때 선택한 커밋으로 롤백할 수 있습니다.

## 미리보기와 게시

- **미리보기**: 샌드박스에서 개발과 테스트를 위한 것으로, 경우에 따라 샌드박스를 수동으로 시작해야 할 수 있습니다.
- **게시/공유**: 사용자가 직접 수행하는 작업으로, 앱을 누구나 접근할 수 있는 환경에 배포합니다.

## 에이전트가 가장 잘하는 일

- 풀스택 제품의 빠른 프로토타이핑
- 영구 저장소를 활용한 CRUD 흐름
- 기본적인 관리자 또는 백오피스 데이터 작업
- 로그인, 데이터, 배포 흐름을 갖춘 엔드투엔드 데모 프로젝트

## 현재의 한계

- 고급 프로덕션 운영(예: 복잡한 SRE와 다중 리전 HA)은 여전히 수동 엔지니어링 작업이 필요합니다.
- 위험도가 높은 프로덕션 상황에서는 출시 전에 보안 검토와 배포 강화를 진행하세요.
