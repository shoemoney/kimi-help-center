# Возможности и ограничения Agent

<SeoMeta
  title="Возможности и ограничения Agent — Справочный центр Kimi"
  description="Узнайте о возможностях Kimi Agent, советах по использованию, ограничениях и лучших практиках для получения оптимальных результатов."
/>

<Callout type="info">
**Kimi Agent** — это помощник на базе ИИ, который автономно выполняет сложные задачи с помощью многошагового рассуждения и интеграции инструментов. В этом руководстве собраны лучшие практики, ограничения и ответы на частые вопросы, чтобы вы могли максимально эффективно использовать режим Agent.
</Callout>

## Советы по использованию

**(1) Перед отправкой задачи**

Четко опишите исходные данные и ограничения: контекст проекта, сценарий использования и особые требования. Так Kimi точнее поймет вашу цель.

**(2) Во время выполнения**

Kimi Agent работает асинхронно в фоновом режиме. Если веб-страница выглядит зависшей или не отвечает, **не нажимайте «Stop»** — это прервет выполнение задачи. Вы можете закрыть страницу: задача продолжит выполняться в фоне, а после завершения вы получите уведомление. Если задача может занять много времени (например, Agent Swarm), пожалуйста, подождите.

**(3) Сценарии с веб-сайтами**

Agent может создавать full-stack-контент, включая frontend-интерфейсы, backend-сервисы и логику постоянного хранения данных. Если проект работает не так, как ожидалось, причина обычно связана с запуском sandbox, инициализацией базы данных, настройкой auth или отсутствием действий по публикации. Стандартный Agent работает в облаке и не может напрямую обращаться к локальным файлам или системам корпоративной интрасети. Для доступа к локальным файлам или интрасети используйте Kimi Claw.

<Callout type="tip">
**Нужен доступ к локальным файлам?** Используйте Kimi Claw для безопасного доступа к локальным файлам и системам корпоративной интрасети. Подробнее см. в [документации Kimi Claw](/kimi-claw/overview).
</Callout>

**(4) Многоходовые диалоги и корректировка задач**
При нескольких раундах диалога и правок Agent может «забыть» часть ранних деталей. Лучше сначала задать рамки задачи и ключевые пункты, а затем вносить изменения постепенно.

**(5) Декомпозиция крупных задач**
Большие и сложные задачи лучше разбить на 2–3 этапа и отправлять их в Kimi пакетами либо использовать Agent Swarm.

**(6) Ограничения на вывод файлов**
В стандартном режиме Agent обычно можно получить только один файл за задачу (например, документ или таблицу). Если нужно несколько файлов (например, одновременно документ Word и PPT), используйте Agent Swarm.

**(7) Ограничения контекста и баланс вывода**
Из-за ограничения контекста больших языковых моделей в 256K символов (примерно 40 000–50 000 китайских иероглифов / около 100 000 английских слов) при обработке больших объемов файлов важно соблюдать баланс между объемом входных данных и результата.

<Callout type="warning">
**Примечание об ограничении контекста**: Agent использует контекстное окно на 256K символов. Для лучших результатов давайте краткий контекст и не перегружайте задачу лишними файлами.
</Callout>

## Важные примечания

<Callout type="warning">
**Расход credit**: задачи Agent расходуют credit из общего пула. Kimi Code также использует этот общий пул, но имеет собственный 5-часовой / недельный rate limit, который применяется только к Kimi Code. Каждая задача Agent обычно расходует 1 единицу credit. Подробную информацию о credit для разных уровней подписки см. в разделе [Credits & Billing](/agent/quota-and-billing).

- 60–720 задач Agent в месяц в зависимости от вашего плана
</Callout>

- **Время выполнения**: в режиме Agent одна задача обычно занимает 5–20 минут. Задачи Agent Swarm могут выполняться дольше. Вы можете закрыть страницу — главное, не нажимайте Stop, чтобы не прервать задачу.
- **Расход credit**: задачи Agent расходуют credit из общего пула, который также использует Kimi Code (у Kimi Code есть собственный 5-часовой / недельный rate limit).
- **Простые задачи**: для простых вопросов и ответов рекомендуется стандартный режим чата — он отвечает быстрее.

<Callout type="warning">
**Соответствие требованиям к контенту**: функции Agent регулируются [Kimi User Service Agreement](https://www.kimi.com/user/agreement/modelUse?version=v2). Создание запрещенного контента не поддерживается; отправка запрещенного контента может привести к приостановке обслуживания.
</Callout>

## FAQ

**В: Что умеет Agent?**

Agent закрывает следующие потребности с помощью нескольких вызовов инструментов:
- **Генерация и редактирование текста**: создание статей, отчетов, документов и т. д. с поддержкой разных стилей письма и форматов.
- **Веб-разработка**: создание full-stack-интерфейсов и сервисов проектов с поддержкой дизайна интерфейса приложения, backend-интеграции, постоянного хранения данных и визуализации данных.
- **Создание слайдов**: специализированный веб-инструмент для генерации полноценных презентаций PPT.
- **Помощь в программировании**: написание и отладка кода на разных языках программирования.

**В: Почему сайт, созданный Agent, не работает?**

Полный проект обычно состоит из трех частей: frontend-интерфейса, backend-сервисов и хранилища данных. Agent может создавать full-stack-контент проекта на всех трех уровнях. Если проект работает не так, как ожидалось, причина обычно связана с запуском sandbox, инициализацией базы данных, настройкой auth или отсутствием действий по публикации.

**В: Какие результаты выдает Agent?**

- Файлы с полностью выполненной задачей
- Предпросмотр развернутого проекта и опубликованные версии
- Загружаемый Zip-архив (находится в `/mnt/okcomputer/output/`)

**В: Какова длина контекста у Agent?**

Agent использует контекст длиной **256K символов** (примерно 40 000–50 000 китайских иероглифов / около 100 000 английских слов).

**В: Как рассчитываются credit Agent?**

Все функции подписки, включая Kimi Code, используют один общий пул credit. Каждая задача Agent обычно учитывается как одна единица credit.
