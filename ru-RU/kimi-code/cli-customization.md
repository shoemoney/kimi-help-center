# Настройка и справочник

Kimi Code CLI предлагает широкие возможности настройки, позволяя адаптировать поведение ИИ и рабочий процесс под ваши задачи.

## Конфигурационный файл

Kimi Code CLI использует `~/.kimi/config.toml` как глобальный конфигурационный файл и поддерживает форматы TOML и JSON. Вы можете настроить:

- **Провайдеры API и модели**: задайте разных провайдеров моделей, endpoint API и ключи.
- **Модель по умолчанию**: укажите модель, которая будет использоваться по умолчанию.
- **Параметры выполнения**: настройте тайм-аут, concurrency (параллелизм), формат вывода и другие параметры времени выполнения.

> Используйте команду `/config`, чтобы быстро открыть конфигурационный файл для редактирования.

## Конфигурация проекта в AGENTS.md

Поместите файл `AGENTS.md` в корень проекта, чтобы передать ИИ контекст на уровне проекта:

- **Описание проекта**: опишите функциональность, архитектуру и технологический стек проекта.
- **Шаги сборки**: как установить зависимости, собрать проект и запустить тесты.
- **Соглашения по коду**: правила именования, структуру каталогов, предпочтения по стилю кода.
- **Особые замечания**: ограничения безопасности, требования к производительности и другие важные условия.

Используйте команду `/init`, чтобы ИИ автоматически просканировал проект и создал начальный `AGENTS.md`. Файл также можно отредактировать вручную, добавив сведения, специфичные для проекта. Файлы `AGENTS.md` можно размещать в любых подкаталогах — ИИ автоматически загрузит подходящие конфигурации.

## Пользовательский системный prompt

Системный prompt ИИ можно настроить несколькими способами:

- **Глобальный системный prompt**: запишите его в `~/.kimi/AGENTS.md` — он применяется ко всем проектам.
- **Системный prompt на уровне проекта**: запишите его в `AGENTS.md` в корне проекта — он применяется только к текущему проекту.
- **Параметр запуска**: используйте флаг `--system-prompt`, чтобы указать prompt при запуске.

Конфигурация на уровне проекта переопределяет глобальную, а параметр запуска имеет наивысший приоритет.

## Интеграция с MCP

Kimi Code CLI поддерживает Model Context Protocol (MCP), позволяя подключать внешние инструменты и источники данных и тем самым расширять возможности ИИ:

- **Конфигурация MCP-сервера**: добавьте адреса MCP-серверов в конфигурационный файл, чтобы ИИ мог вызывать внешние инструменты.
- **Встроенная поддержка MCP**: некоторые часто используемые MCP-инструменты уже встроены и не требуют дополнительной настройки.
- **Пользовательские MCP-серверы**: вы можете разработать собственные MCP-серверы для предметно-ориентированных возможностей.

Конфигурацию MCP можно разместить в `~/.kimi/config.toml` или в конфигурационных файлах на уровне проекта.

## Переменные окружения

Kimi Code CLI поддерживает настройку через переменные окружения — это удобно для CI/CD-пайплайнов и скриптов:

| Переменная окружения | Описание |
| --- | --- |
| `KIMI_API_KEY` | Ключ API |
| `KIMI_BASE_URL` | Пользовательский endpoint API |
| `KIMI_MODEL` | Имя модели по умолчанию |
| `KIMI_MAX_TOKENS` | Максимальное количество token на выходе |

Переменные окружения имеют приоритет над настройками в конфигурационном файле.

## Дополнительные справочные материалы

- **Справочник slash-команд**: используйте `/help`, чтобы посмотреть все доступные команды.
- **Справочник параметров CLI**: выполните `kimi --help`, чтобы посмотреть все параметры запуска.
- **Официальная документация**: посетите [документацию Kimi Code](https://www.kimi.com/code/docs/en/), чтобы получить самую свежую и полную информацию.
