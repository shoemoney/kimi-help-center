# Цели

Цели помогают Kimi Code из хода в ход двигаться к заданному результату. Обычный промпт указывает, что делать дальше; цель же описывает, что должно стать истинным. Используйте `/goal`, когда у задачи есть понятный критерий завершения, но следующий полезный шаг зависит от того, что агент выяснит в процессе — например, нужно исправить набор падающих тестов или найти первопричину сломанной сборки.

## Запустить цель

Напишите задачу после `/goal`:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Исправь ошибки, перечисленные в трекере задач.",
    },
  ]}
/>

Kimi Code сохранит задачу, отправит её как следующее сообщение пользователя и включит режим целей. После каждого хода он проверяет, выполнена ли цель, заблокирована, приостановлена или всё ещё активна.

Цели работают лучше всего, когда в формулировке указаны конечный результат и подтверждение, по которому понятно, что он достигнут:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Исправь все ошибки с меткой checkout-regression, добавь или обнови тесты для каждого исправления и запусти набор тестов checkout",
    },
  ]}
/>

Не задавайте цели, которые обозначают только общее направление:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Найди все ошибки в этой кодовой базе.",
    },
  ]}
/>

Такая цель не объясняет, что считать успехом, что проверять и когда остановиться. Агент может сразу заблокировать цель или работать над ней гораздо дольше, чем вы ожидали.

### Когда использовать цели

Используйте цели для работы с понятной точкой завершения и проверяемым подтверждением результата.

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Исправь все падающие тесты checkout и успешно запусти набор тестов checkout.",
    },
  ]}
/>

Kimi Code может изучить вывод тестов, изменить файлы, повторно запустить проверки и определить, что цель выполнена.

Используйте цели, когда задача может потребовать нескольких ходов для расследования и исправления.

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Выясни, почему падает релизная сборка, исправь первопричину и проверь, что сборка проходит.",
    },
  ]}
/>

Цель описывает результат, поэтому агент может менять подход, если первая зацепка окажется не первопричиной.

Используйте цели для последовательной работы, которая должна продолжаться без дополнительного промпта.

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Обнови реализацию функции, добавь документацию, запусти тесты и кратко опиши изменённые файлы.",
    },
  ]}
/>

Это удобно, когда вы уже знаете, какие проверки или артефакты должны появиться до завершения работы.

### Когда не использовать цели

Не используйте цели для широких тем или открытых обсуждений.

**Контрпример:**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Привет!",
    },
  ]}
/>

<Callout type="warning">
Агенты сразу пометят такие не-цели как выполненные.
</Callout>

Не используйте цели для задач, которые заведомо невозможны или неразрешимы.

**Контрпример:**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Докажи, что 1 + 1 = 3.",
    },
  ]}
/>

<Callout type="warning">
Агенты пометят цель как заблокированную, если она кажется невозможной или неразрешимой.
</Callout>

Не используйте цели с неоднозначными или слишком сложными формулировками.

**Контрпример:**

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal Создай видеоигру в одном HTML-файле.",
    },
  ]}
/>

<Callout type="warning">
Агенты могут выполнить такие цели, но после долгой работы результат может оказаться неожиданным.
</Callout>

## Управлять жизненным циклом

Используйте тот же набор команд, чтобы просматривать текущую цель или управлять ею:

| Команда | Действие |
| --- | --- |
| `/goal` or `/goal status` | Показать текущую цель и ход выполнения |
| `/goal pause` | Приостановить активную цель, не удаляя её |
| `/goal resume` | Возобновить приостановленную или заблокированную цель |
| `/goal cancel` | Удалить текущую цель |
| `/goal replace <objective>` | Заменить текущую цель новой задачей |

Цель может остановиться тремя способами:

- **выполнена**: задача завершена, Kimi Code очищает цель, а агент кратко объясняет, как выполнил работу
- **приостановлена**: вы приостановили цель, прервали ход, возобновили сеанс с активной целью либо произошла ошибка модели, провайдера или среды выполнения
- **заблокирована**: Kimi Code нужны дополнительные данные, цель невозможно выполнить в заявленном виде или достигнут лимит бюджета. Когда агент блокирует цель, он пишет короткое сообщение с объяснением причины.

Прописывайте условия остановки прямо в формулировке цели. У `/goal` нет отдельного флага для лимита остановки.

## Ставить следующие цели в очередь

Иногда агенты выполняют цель слишком быстро. Пользователей может разочаровывать, что за раз можно назначить только одну цель. Многие заранее знают, какими целями хотят заняться дальше. Раньше им приходилось ждать завершения текущей цели, открывать TUI и вручную отправлять следующую.

Используйте `/goal next`, когда у вас уже есть следующая работа, но вы не хотите прерывать текущую цель:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal next Обнови примечания к релизу после успешного прохождения тестов",
    },
  ]}
/>

Пока выполняется текущая цель, следующие цели не видны агенту. Когда текущая цель завершится, Kimi Code запустит первую цель из очереди так же, как если бы пользователь ввёл `/goal <objective>`.

Если активной цели нет, `/goal next <objective>` запускает указанную задачу сразу. Команда ведёт себя как `/goal <objective>` и перед запуском цели показывает статусное сообщение.

Управляйте следующими целями интерактивно:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal next manage",
    },
  ]}
/>

В менеджере используйте <kbd>↑</kbd> / <kbd>↓</kbd> для просмотра, <kbd>Space</kbd> — чтобы выбрать цель для перемещения, <kbd>↑</kbd> / <kbd>↓</kbd> — чтобы изменить её порядок, <kbd>E</kbd> — чтобы отредактировать, <kbd>D</kbd> — чтобы удалить, и <kbd>Esc</kbd> — чтобы отменить. При редактировании используйте <kbd>Shift-Enter</kbd> или <kbd>Ctrl-J</kbd>, чтобы добавить новую строку, и <kbd>Enter</kbd>, чтобы сохранить.

Если текущая цель приостановлена, отменена или заблокирована, Kimi Code не запускает следующую цель из очереди. Когда цель заблокирована и в очереди есть следующие цели, TUI напоминает, что они ждут завершения текущей.

## Пользуйтесь режимом целей осмотрительно

Режим целей полезен для работы, которую можно проверить по файлам, тестам, выводу команд, созданным артефактам или понятному письменному отчёту. Он менее полезен для разового исправления или вопроса, на который нужен один ответ.

В режиме разрешений `manual` работа над целью может приостанавливаться для подтверждения вызовов инструментов. Для автономной работы выбирайте режим разрешений, соответствующий риску репозитория и командам, которые может запускать агент.

В неинтерактивном режиме промпта поддерживается только создание цели:

<CodePreview
  files={[
    {
      name: "command.sh",
      language: "bash",
      content: "kimi -p \"/goal Исправь падающий тест checkout\"",
    },
  ]}
/>

Режим промпта завершается с кодом `0`, когда цель выполнена, с кодом `3`, когда она заблокирована, и с кодом `6`, когда она приостановлена. `/goal next` и другие команды управления доступны в TUI.
