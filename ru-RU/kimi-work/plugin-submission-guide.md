# Создание и отправка плагинов

Если вы хотите подключить свой продукт или сервис к Kimi, чтобы пользователи могли обращаться к его функциям в диалоге, следуйте этому руководству для создания, тестирования и отправки плагина в официальный магазин Kimi.

## Что такое плагин Kimi?

Плагин Kimi соединяет ваш продукт с Kimi. Он помогает Kimi понимать, когда ваш продукт может быть полезен, и предоставляет необходимые рабочие процессы или инструменты. Плагин может включать:

- **Только навыки**: повторяемые рабочие процессы, адаптированные под ваш продукт или задачу.
- **Только MCP**: инструменты и сервисы, доступные Kimi через сервер MCP.
- **Навыки и MCP**: сочетание инструментов продукта с рабочими процессами, которые помогают Kimi эффективно их использовать.

## Перед началом работы

Сначала [скачайте и установите Kimi Work](https://www.kimi.com/products/kimi-work). Подготовьте следующее:

- Название, описание и логотип плагина
- Основные задачи, которые пользователи смогут выполнять с помощью естественного языка
- URL сервера MCP, если применимо

<Callout type="warning">
Если логотип плагина содержит товарный знак или бренд третьей стороны, свяжитесь с правообладателем и получите письменное разрешение перед отправкой.
</Callout>

## Шаг 1: Создание и тестирование плагина

1. Откройте Kimi Work, введите "/" в диалоге и выберите **Plugin Builder**.
2. Опишите плагин и укажите подготовленные данные. Если у вас уже есть плагин для Codex, Claude или другой платформы, предоставьте его файлы или URL проекта и следуйте инструкциям для конвертации.

3. Перейдите в **Plugins** → **Personal**, найдите плагин и установите его.

4. Протестируйте основные функции в новом диалоге, включая стандартные и граничные случаи. Сохраните как минимум три тестовых запроса.
5. Следуйте инструкциям Plugin Builder, чтобы получить ZIP-архив плагина.

Для плагина с поддержкой MCP также протестируйте процесс аутентификации:

- **Без аутентификации**: пользователи могут использовать плагин сразу после установки.
- **OAuth**: страница авторизации третьей стороны должна открываться при первой установке.
- **Аутентификация через CLI**: установка не запускает авторизацию. При первом вызове плагина пользователи завершают авторизацию в диалоге. После успешной авторизации повторная авторизация в других диалогах обычно не требуется.

## Шаг 2: Отправка заявки

После создания и тестирования плагина заполните [форму отправки плагинов Kimi](https://moonshot.feishu.cn/share/base/form/shrcnZcnxlNJlbw845KoVgjEhkh) и загрузите ZIP-архив.

Форма запрашивает:

| Пункт | Требование |
| --- | --- |
| Название, описание и ZIP-архив плагина | Обязательно |
| Тип плагина | Только навыки, только MCP или гибрид |
| Аутентификация MCP | Обязательно для плагинов только с MCP и гибридных |
| Целевые регионы | Китай, зарубежные страны или оба варианта |
| Особенности и тестовые запросы | Минимум три тестовых запроса |
| Интерес к совместному маркетингу и материалы | Материалы необязательны, нужны только для обсуждения совместного маркетинга |
| Статус авторизации и соответствия | Укажите пункты, требующие дополнительного обсуждения |
| Контактный email | Используется для обновлений по рассмотрению и запросов информации |
| Компания или команда, связанный сайт и примечания | Необязательно |

<Callout type="warning">
Не включайте пароли, токены, API-ключи, приватные ключи или другие секреты в форму или ZIP-архив. Если пользователям нужен собственный ключ, объясните только, как его получить и настроить.
</Callout>

## Дальнейшие действия

Команда Kimi рассмотрит заявку и ZIP-архив. Если плагин пройдет проверку или потребуются дополнительные данные или изменения, мы свяжемся с вами по указанному email и сообщим следующие шаги.

## Часто задаваемые вопросы

### Можно ли отправить плагин без сервера MCP?

Да. Поддерживаются плагины только с навыками. Выберите **Только навыки** как тип плагина.

### Можно ли отправить плагин для Codex, Claude или другой платформы?

Да. На шаге 1 предоставьте файлы существующего плагина или URL проекта Plugin Builder и следуйте инструкциям для конвертации. Установите и протестируйте конвертированный плагин в Kimi Work перед отправкой полученного ZIP-архива.

### Какие методы аутентификации MCP поддерживаются?

В настоящее время поддерживаются три метода:

- **Без аутентификации**: Пользователи могут использовать плагин сразу после установки без входа или дополнительной проверки.
- **OAuth**: При первой установке плагина пользователи автоматически перенаправляются на страницу авторизации стороннего продукта.
- **Аутентификация через CLI**: Установка не запускает процесс авторизации. При первом вызове плагина в диалоге пользователи завершают авторизацию по инструкциям. После успешной авторизации повторная авторизация обычно не требуется.

Протестируйте процесс, соответствующий вашему методу аутентификации. Если плагин с OAuth не перенаправляет при первой установке или плагин с CLI-аутентификацией постоянно запрашивает авторизацию, проверьте настройки аутентификации сервера MCP перед отправкой и опишите проблему в **Дополнительных примечаниях**.

### Как выглядит процесс авторизации OAuth?

Для сервера MCP с поддержкой OAuth Plugin Builder определяет соответствующую информацию авторизации из URL сервера. После создания плагина пользователи при первой установке перенаправляются на страницу авторизации стороннего продукта.

### Что делать, если я хочу обсудить более широкое партнерство с Kimi?

Сначала завершите процесс создания, тестирования и отправки плагина по этому руководству. Если вы хотите обсудить другие формы сотрудничества помимо размещения плагина, кратко опишите предложение в **Дополнительных примечаниях**. Команда Kimi может связаться с вами в зависимости от обстоятельств.

### Гарантирует ли отправка заявки размещение плагина?

Нет. Команда Kimi оценивает функциональность, пользовательский опыт, безопасность, надежность сервиса и статус авторизации плагина.
