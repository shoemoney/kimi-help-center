# Почему не работает?

<Callout type="tip">
Фулстек-проект включает **пользовательский интерфейс, бэкенд-сервисы и постоянное хранилище**. Kimi Agent может создать все три компонента, но успешный запуск зависит от настройки окружения, конфигурации аутентификации и действий по публикации.
</Callout>

Если ваше приложение работает не так, как ожидалось, причина обычно не в отсутствии бэкенд-возможностей. Чаще всего не завершен один из шагов: preview, настройка аутентификации, базы данных или публикации.

## Фулстек-процесс 

1. **Генерация**: агент создает фронтенд + бэкенд + схему базы данных и логику работы с данными.
2. **Preview**: запуск в sandbox для локального фулстек-тестирования; в некоторых случаях может потребоваться ручной старт.
3. **Версионирование**: агент может использовать инструменты версионирования и автоматически создавать коммиты.
4. **Откат**: можно вернуться к любой предыдущей версии коммита.
5. **Публикация / доступ**: приложение разворачивается на публичном URL только после ручной публикации.

## Частые причины сбоев 

| Признак | Вероятная причина | Что сделать |
|----------|-------------|------------|
| Фронтенд загружается, но API не отвечает | Sandbox runtime не запущен | Запустите sandbox и повторите preview |
| Данные не сохраняются или не отображаются | База данных не инициализирована или миграции не применены | Повторно выполните настройку базы данных или шаг миграции |
| Не удается войти | Сценарий аутентификации настроен неправильно | Проверьте конфигурацию входа через Kimi и настройки callback |
| Другие пользователи не могут открыть приложение | Приложение не опубликовано | Нажмите **Publish/Share**, чтобы развернуть его |
| Последние изменения нарушили работу функций | Регрессия в последней версии | Откатитесь к стабильному коммиту |

## Поддержка аутентификации

- **Фаза 1**: поддерживает вход через **Kimi**.
- **Следующая фаза**: будут добавлены дополнительные OAuth-провайдеры.
- **Также поддерживается**: агент может сгенерировать стандартный вход по email и паролю на основе базы данных.

## Версии и откат

- Агент поддерживает новые инструменты версионирования и может самостоятельно выполнять `git commit` во время разработки.
- При необходимости можно просмотреть историю версий и откатиться к выбранному коммиту.

## Preview и публикация

- **Preview**: используется для разработки и тестирования в sandbox; в некоторых сценариях может потребоваться запустить sandbox вручную.
- **Publish/Share**: ручное действие пользователя, которое разворачивает приложение в общедоступной среде.

## Где агент особенно полезен

- Быстрое прототипирование фулстек-продуктов
- CRUD-сценарии с постоянным хранилищем
- Базовые административные операции и работа с back-office-данными
- Сквозные демопроекты со входом, данными и процессом развертывания

## Текущие ограничения

- Сложные production-операции — например, комплексные SRE-процессы и multi-region HA — по-прежнему требуют ручной инженерной работы.
- Для production-сценариев с высоким уровнем риска перед релизом проведите проверку безопасности и усиление защиты развертывания.
