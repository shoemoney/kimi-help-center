# เป้าหมาย

เป้าหมายช่วยให้ Kimi Code ทำงานมุ่งสู่ผลลัพธ์ที่กำหนดไว้ตลอดการสนทนาแต่ละรอบ ต่างจากพรอมต์ทั่วไปที่บอกว่าต้องทำอะไรในขั้นถัดไป เป้าหมายจะบอกว่าอะไรต้องเป็นจริง ใช้ `/goal` เมื่องานมีเส้นชัยที่ชัดเจน แต่ขั้นตอนที่เป็นประโยชน์ถัดไปขึ้นอยู่กับสิ่งที่ตัวแทนเรียนรู้ระหว่างทำงาน เช่น แก้ไขชุดของเทสต์ที่ล้มเหลว หรือไล่หาต้นตอของบิลด์ที่พัง

## เริ่มเป้าหมาย

เขียนวัตถุประสงค์ต่อท้าย `/goal`:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal แก้ไขบั๊กที่แสดงอยู่ใน issue tracker",
    },
  ]}
/>

Kimi Code จะบันทึกวัตถุประสงค์ ส่งเป็นข้อความผู้ใช้ถัดไป และเริ่มโหมดเป้าหมาย หลังจบแต่ละรอบ ระบบจะตรวจสอบว่าเป้าหมายเสร็จสมบูรณ์ ถูกบล็อก ถูกหยุดชั่วคราว หรือยังดำเนินอยู่

เป้าหมายจะได้ผลดีที่สุดเมื่อวัตถุประสงค์ระบุทั้งเส้นชัยและหลักฐานที่ใช้พิสูจน์:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal แก้ไขบั๊กทุกตัวที่มีป้ายกำกับ checkout-regression เพิ่มหรืออัปเดตเทสต์สำหรับการแก้ไขแต่ละครั้ง แล้วรันชุดเทสต์ของ checkout",
    },
  ]}
/>

หลีกเลี่ยงเป้าหมายที่ระบุเพียงทิศทางกว้าง ๆ:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal ค้นหาบั๊กทั้งหมดในโค้ดเบสนี้",
    },
  ]}
/>

เป้าหมายนี้ไม่ได้บอกว่าอะไรนับเป็นความสำเร็จ ต้องตรวจสอบอะไร หรือควรหยุดเมื่อใด ตัวแทนอาจถูกบล็อกทันที หรือทำงานต่อนานเกินกว่าที่คุณคาดไว้

### เมื่อใดควรใช้เป้าหมาย

ใช้เป้าหมายกับงานที่มีเส้นชัยชัดเจนและมีหลักฐานที่ตรวจสอบได้

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal แก้ไขเทสต์ของ checkout ที่ล้มเหลวทุกตัว และรันชุดเทสต์ของ checkout ให้สำเร็จ",
    },
  ]}
/>

Kimi Code สามารถตรวจสอบผลลัพธ์ของเทสต์ แก้ไขไฟล์ รันการตรวจสอบซ้ำ และตัดสินใจว่าเป้าหมายเสร็จสมบูรณ์เมื่อใด

ใช้เป้าหมายเมื่องานอาจต้องการการตรวจสอบและซ่อมแซมหลายรอบ

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",

    },
  ]}
/>

เป้าหมายอธิบายผลลัพธ์ ตัวแทนจึงสามารถปรับตัวได้เมื่อเบาะแสแรกไม่ใช่ต้นตอที่แท้จริง

ใช้เป้าหมายกับงานที่มีลำดับและควรดำเนินต่อโดยไม่ต้องป้อนพรอมต์เพิ่ม

<CodePreview
  files={[

    },
  ]}
/>

วิธีนี้มีประโยชน์เมื่อคุณรู้อยู่แล้วว่าต้องมีการตรวจสอบหรือผลงานอะไรบ้างก่อนงานจะเสร็จ

## จัดการวงจรชีวิต

ใช้ชุดคำสั่งเดียวกันในการตรวจสอบหรือควบคุมเป้าหมายปัจจุบัน:

| คำสั่ง | การทำงาน |
| --- | --- |
| `/goal` หรือ `/goal status` | แสดงเป้าหมายปัจจุบันและความคืบหน้า |
| `/goal pause` | หยุดเป้าหมายที่ดำเนินอยู่ชั่วคราวโดยไม่ลบทิ้ง |
| `/goal resume` | ดำเนินเป้าหมายที่หยุดชั่วคราวหรือถูกบล็อกต่อ |
| `/goal cancel` | ลบเป้าหมายปัจจุบัน |
| `/goal replace <objective>` | แทนที่เป้าหมายปัจจุบันด้วยวัตถุประสงค์ใหม่ |

เป้าหมายสามารถหยุดได้สามแบบ:

- **complete**: วัตถุประสงค์เสร็จสิ้น Kimi Code ล้างเป้าหมาย และตัวแทนสรุปวิธีที่ทำงานจนเสร็จ
- **paused**: คุณหยุดชั่วคราว ขัดจังหวะรอบการทำงาน กลับเข้าเซสชันที่มีเป้าหมายดำเนินอยู่ หรือพบข้อผิดพลาดจากโมเดล ผู้ให้บริการ หรือรันไทม์
- **blocked**: Kimi Code ต้องการข้อมูลเพิ่มเติม ไม่สามารถทำเป้าหมายตามที่ระบุได้ หรือถึงขีดจำกัดงบประมาณ เมื่อตัวแทนบล็อกเป้าหมาย จะเขียนข้อความสั้น ๆ อธิบายเหตุผล

เขียนเงื่อนไขการหยุดไว้ในวัตถุประสงค์ `/goal` ไม่มีแฟล็กจำกัดการหยุดแยกต่างหาก

## จัดคิวเป้าหมายถัดไป

บางครั้งตัวแทนทำเป้าหมายเสร็จเร็วเกินไป ผู้ใช้อาจผิดหวังที่กำหนดได้เพียงทีละเป้าหมาย หลายคนรู้อยู่แล้วว่าจะทำเป้าหมายใดต่อไป แต่ต้องรอให้เป้าหมายปัจจุบันเสร็จ เปิด TUI แล้วป้อนเป้าหมายถัดไปด้วยตนเอง

ใช้ `/goal next` เมื่อคุณมีงานพร้อมเพิ่มแต่ไม่อยากขัดจังหวะเป้าหมายปัจจุบัน:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal next อัปเดต release notes หลังจากเทสต์ผ่าน",
    },
  ]}
/>

ตัวแทนจะมองไม่เห็นเป้าหมายถัดไปขณะที่เป้าหมายปัจจุบันกำลังดำเนินอยู่ เมื่อเป้าหมายปัจจุบันเสร็จสิ้น Kimi Code จะเริ่มเป้าหมายถัดไปลำดับแรกในลักษณะเดียวกับที่ผู้ใช้ป้อน `/goal <objective>`

หากไม่มีเป้าหมายที่ดำเนินอยู่ `/goal next <objective>` จะเริ่มวัตถุประสงค์นั้นทันที โดยทำงานเหมือน `/goal <objective>` และแสดงข้อความสถานะก่อนเป้าหมายจะเริ่ม

จัดการเป้าหมายถัดไปแบบโต้ตอบ:

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "/goal next manage",
    },
  ]}
/>

ในตัวจัดการ ใช้ <kbd>↑</kbd> / <kbd>↓</kbd> เพื่อเลื่อนดู <kbd>Space</kbd> เพื่อเลือกเป้าหมายที่จะย้าย <kbd>↑</kbd> / <kbd>↓</kbd> เพื่อจัดลำดับใหม่ <kbd>E</kbd> เพื่อแก้ไข <kbd>D</kbd> เพื่อลบ และ <kbd>Esc</kbd> เพื่อยกเลิก ขณะแก้ไข ใช้ <kbd>Shift-Enter</kbd> หรือ <kbd>Ctrl-J</kbd> เพื่อขึ้นบรรทัดใหม่ และ <kbd>Enter</kbd> เพื่อบันทึก

หากเป้าหมายปัจจุบันถูกหยุดชั่วคราว ยกเลิก หรือบล็อก Kimi Code จะไม่เริ่มเป้าหมายถัดไป เมื่อเป้าหมายถูกบล็อกและมีเป้าหมายถัดไปรออยู่ TUI จะเตือนคุณว่าเป้าหมายเหล่านั้นกำลังรอให้งานเสร็จสิ้น

## ใช้โหมดเป้าหมายอย่างระมัดระวัง

โหมดเป้าหมายมีประโยชน์กับงานที่ตรวจสอบได้ด้วยไฟล์ เทสต์ ผลลัพธ์คำสั่ง ผลงานที่สร้างขึ้น หรือรายงานที่เขียนไว้อย่างชัดเจน แต่จะมีประโยชน์น้อยกว่าสำหรับการแก้ไขครั้งเดียวหรือคำถามที่ต้องการเพียงคำตอบเดียว

ในโหมดสิทธิ์ `manual` งานเป้าหมายอาจหยุดชั่วคราวเพื่อรอการอนุมัติการเรียกใช้เครื่องมือ สำหรับงานที่ทำงานโดยไม่มีผู้ดูแล ให้ใช้โหมดสิทธิ์ที่เหมาะกับความเสี่ยงของรีโพซิทอรีและคำสั่งที่ตัวแทนอาจเรียกใช้

ในโหมดพรอมต์แบบไม่โต้ตอบ รองรับเฉพาะการสร้างเป้าหมายเท่านั้น:

<CodePreview
  files={[
    {
      name: "command.sh",
      language: "bash",
      content: "kimi -p \"/goal แก้ไขเทสต์ของ checkout ที่ล้มเหลว\"",
    },
  ]}
/>

โหมดพรอมต์จะออกด้วยโค้ด `0` เมื่อเป้าหมายเสร็จสมบูรณ์ `3` เมื่อถูกบล็อก และ `6` เมื่อหยุดชั่วคราว `/goal next` และคำสั่งจัดการอื่น ๆ เป็นการควบคุมผ่าน TUI
