# สร้างและส่งปลั๊กอิน

หากคุณต้องการเชื่อมต่อผลิตภัณฑ์หรือบริการของคุณกับ Kimi เพื่อให้ผู้ใช้สามารถเข้าถึงความสามารถของมันในการสนทนา ให้ทำตามคู่มือนี้เพื่อสร้าง ทดสอบ และส่งปลั๊กอินสำหรับตลาดปลั๊กอิน Kimi อย่างเป็นทางการ

## ปลั๊กอิน Kimi คืออะไร?

ปลั๊กอิน Kimi เชื่อมต่อผลิตภัณฑ์ของคุณกับ Kimi มันช่วยให้ Kimi เข้าใจเมื่อผลิตภัณฑ์ของคุณมีประโยชน์และให้เวิร์กโฟลว์หรือเครื่องมือที่จำเป็นเพื่อช่วยผู้ใช้ ปลั๊กอินสามารถประกอบด้วย:

- **ทักษะอย่างเดียว**: เวิร์กโฟลว์ที่ใช้ซ้ำได้ซึ่งปรับแต่งสำหรับผลิตภัณฑ์หรือกรณีใช้ของคุณ
- **MCP อย่างเดียว**: เครื่องมือและบริการที่เปิดให้ Kimi ใช้งานผ่านเซิร์ฟเวอร์ MCP
- **ทักษะและ MCP**: เครื่องมือผลิตภัณฑ์รวมกับเวิร์กโฟลว์ที่ช่วยให้ Kimi ใช้งานได้อย่างมีประสิทธิภาพ

## ก่อนเริ่มต้น

ก่อนอื่น [ดาวน์โหลดและติดตั้ง Kimi Work](https://www.kimi.com/products/kimi-work) เตรียมสิ่งต่อไปนี้:

- ชื่อ คำอธิบาย และโลโก้ของปลั๊กอิน
- งานหลักที่ผู้ใช้ควรสามารถทำเสร็จด้วยภาษาธรรมชาติ
- URL เซิร์ฟเวอร์ MCP (ถ้ามี)

<Callout type="warning">
หากโลโก้ปลั๊กอินมีผลิตภัณฑ์ แบรนด์ หรือเครื่องหมายการค้าของบุคคลที่สาม ให้ติดต่อผู้ถือสิทธิ์ที่เกี่ยวข้องและรับอนุญาตเป็นลายลักษณ์อักษรที่จำเป็นก่อนส่ง
</Callout>

## ขั้นตอนที่ 1: สร้างและทดสอบปลั๊กอิน

1. เปิด Kimi Work พิมพ์ "/" ในบทสนทนาและเลือก **Plugin Builder**
2. อธิบายปลั๊กอินและให้ข้อมูลที่คุณเตรียมไว้ หากคุณมีปลั๊กอินจาก Codex, Claude หรือแพลตฟอร์มอื่นอยู่แล้ว ให้ระบุไฟล์หรือ URL โปรเจกต์และทำตามคำแนะนำเพื่อแปลงมัน

3. ไปที่ **ปลั๊กอิน** → **ส่วนตัว** ค้นหาปลั๊กอินและติดตั้งมัน

4. ทดสอบความสามารถหลักในบทสนทนาใหม่ รวมถึงกรณีปกติและกรณีขอบเขต เก็บตัวอย่างคำสั่งทดสอบที่เป็นตัวแทนอย่างน้อยสามตัวอย่าง
5. ทำตามคำแนะนำของ Plugin Builder เพื่อรับไฟล์ ZIP ปลั๊กอินที่สมบูรณ์

สำหรับปลั๊กอินที่ใช้ MCP ให้ทดสอบขั้นตอนการยืนยันตัวตนด้วย:

- **ไม่มีการยืนยันตัวตน**: ผู้ใช้สามารถใช้ปลั๊กอินได้ทันทีหลังการติดตั้ง
- **OAuth**: หน้าอนุญาตของบุคคลที่สามควรเปิดระหว่างการติดตั้งครั้งแรก
- **การยืนยันตัวตน CLI**: การติดตั้งไม่เริ่มการอนุญาต ครั้งแรกที่ผู้ใช้เรียกใช้ปลั๊กอิน พวกเขาจะทำการยืนยันตัวตนในบทสนทนา หลังยืนยันสำเร็จ โดยทั่วไปพวกเขาไม่จำเป็นต้องยืนยันอีกในบทสนทนาอื่น

## ขั้นตอนที่ 2: สมัครส่งปลั๊กอิน

หลังจากสร้างและทดสอบปลั๊กอินแล้ว ให้กรอก[แบบฟอร์มส่งปลั๊กอิน Kimi](https://moonshot.feishu.cn/share/base/form/shrcnZcnxlNJlbw845KoVgjEhkh) และอัปโหลดไฟล์ ZIP ปลั๊กอิน

แบบฟอร์มถามเกี่ยวกับ:

| รายการ | ความต้องการ |
| --- | --- |
| ชื่อปลั๊กอิน คำอธิบาย และไฟล์ ZIP | จำเป็น |
| ประเภทปลั๊กอิน | ทักษะอย่างเดียว, MCP อย่างเดียว, หรือแบบผสม |
| การยืนยันตัวตน MCP | จำเป็นสำหรับปลั๊กอิน MCP อย่างเดียวและแบบผสม |
| ภูมิภาคที่ตั้งใจ | ประเทศจีนแผ่นดินใหญ่, ต่างประเทศ, หรือทั้งสองอย่าง |
| จุดเด่นและตัวอย่างคำสั่งทดสอบแนะนำ | ตัวอย่างคำสั่งทดสอบอย่างน้อยสามตัวอย่าง |
| ความสนใจร่วมการตลาดและวัสดุ | วัสดุเป็นทางเลือกและจำเป็นเฉพาะหากต้องการหารือร่วมการตลาด |
| สถานะการอนุญาตและความสอดคล้อง | ระบุรายการที่ต้องการหารือเพิ่มเติม |
| อีเมลติดต่อ | ใช้สำหรับอัปเดตการตรวจสอบและคำขอข้อมูลเพิ่มเติม |
| บริษัทหรือทีม เว็บไซต์ที่เกี่ยวข้อง และหมายเหตุ | ทางเลือก |

<Callout type="warning">
อย่ารวมรหัสผ่าน โทเค็น คีย์ API คีย์ส่วนตัว หรือความลับอื่นๆ ในแบบฟอร์มหรือไฟล์ ZIP ปลั๊กอิน หากผู้ใช้ต้องการคีย์ของตนเอง ให้อธิบายเพียงวิธีที่พวกเขาได้รับและกำหนดค่า
</Callout>

## ขั้นตอนต่อไป

ทีม Kimi จะตรวจสอบใบสมัครและไฟล์ ZIP ปลั๊กอิน หากปลั๊กอินผ่านการตรวจสอบ หรือหากเราต้องการข้อมูลหรือการเปลี่ยนแปลงเพิ่มเติม เราจะติดต่อคุณที่อีเมลที่ระบุและแจ้งขั้นตอนต่อไป

## คำถามที่พบบ่อย

### ฉันสามารถส่งปลั๊กอินโดยไม่มีเซิร์ฟเวอร์ MCP ได้ไหม?

ได้ ปลั๊กอินทักษะอย่างเดียวได้รับการสนับสนุน เลือก **ทักษะอย่างเดียว** เป็นประเภทปลั๊กอิน

### ฉันสามารถส่งปลั๊กอินจาก Codex, Claude หรือแพลตฟอร์มอื่นได้ไหม?

ได้ ในขั้นตอนที่ 1 ให้ระบุไฟล์ปลั๊กอินที่มีอยู่หรือ URL โปรเจกต์ให้ Plugin Builder และทำตามคำแนะนำเพื่อแปลงมัน ติดตั้งและทดสอบปลั๊กอินที่แปลงแล้วใน Kimi Work ก่อนส่งไฟล์ ZIP ที่สร้างขึ้น

### วิธีการยืนยันตัวตน MCP ใดที่ได้รับการสนับสนุน?

ปัจจุบันสนับสนุนสามวิธีต่อไปนี้:

- **ไม่มีการยืนยันตัวตน**: ผู้ใช้สามารถใช้ปลั๊กอินได้ทันทีหลังการติดตั้งโดยไม่ต้องลงชื่อเข้าใช้หรือยืนยันตัวตนอื่น
- **OAuth**: ผู้ใช้จะถูกเปลี่ยนเส้นทางไปยังหน้าอนุญาตของผลิตภัณฑ์บุคคลที่สามโดยอัตโนมัติเมื่อติดตั้งปลั๊กอินครั้งแรก พวกเขาสามารถใช้ปลั๊กอินหลังการอนุญาต
- **การยืนยันตัวตน CLI**: การติดตั้งไม่เริ่มขั้นตอนการอนุญาต ครั้งแรกที่ผู้ใช้เรียกใช้ปลั๊กอินในบทสนทนา พวกเขาจะทำการยืนยันตัวตนโดยใช้คำแนะนำที่แสดงในบทสนทนา หลังยืนยันสำเร็จ โดยทั่วไปพวกเขาไม่จำเป็นต้องยืนยันอีกในบทสนทนาอื่น

ทดสอบขั้นตอนที่ตรงกับวิธีการยืนยันตัวจริงของปลั๊กอินของคุณ หากปลั๊กอิน OAuth ไม่เปลี่ยนเส้นทางระหว่างการติดตั้งครั้งแรก หรือปลั๊กอินที่ใช้ CLI ขอให้ผู้ใช้ยืนยันตัวตนซ้ำๆ ให้ตรวจสอบการกำหนดค่าการยืนยันตัวตนของเซิร์ฟเวอร์ MCP ก่อนส่งใบสมัครและอธิบายปัญหาใน **หมายเหตุเพิ่มเติม**

### ขั้นตอนการอนุญาต OAuth เป็นอย่างไร?

สำหรับเซิร์ฟเวอร์ MCP ที่เปิดใช้งาน OAuth, Plugin Builder จะระบุข้อมูลการอนุญาตที่เกี่ยวข้องจาก URL เซิร์ฟเวอร์ MCP หลังสร้างปลั๊กอิน ผู้ใช้จะถูกนำไปยังหน้าอนุญาตของผลิตภัณฑ์บุคคลที่สามครั้งแรกที่พวกเขาติดตั้งมัน

### ฉันต้องการสำรวจความร่วมมือที่กว้างขึ้นกับ Kimi ควรทำอย่างไร?

ให้ทำกระบวนการสร้าง ทดสอบ และส่งปลั๊กอินในคู่มือนี้ให้เสร็จก่อน หากคุณต้องการสำรวจรูปแบบความร่วมมืออื่นนอกเหนือจากการขึ้นแสดงปลั๊กอิน ให้อธิบายข้อเสนอของคุณโดยย่อใน **หมายเหตุเพิ่มเติม** ทีม Kimi อาจติดต่อคุณตามสถานการณ์

### การส่งใบสมัครรับประกันการขึ้นแสดงไหม?

ไม่ ทีม Kimi จะประเมินฟังก์ชันการทำงาน ประสบการณ์ผู้ใช้ ความปลอดภัย ความน่าเชื่อถือของบริการ และสถานะการอนุญาตที่เกี่ยวข้องของปลั๊กอิน
