# ทำไมจึงใช้งานไม่ได้?

<Callout type="tip">
โปรเจกต์ full-stack ประกอบด้วย **ส่วนหน้า UI บริการแบ็กเอนด์ และพื้นที่จัดเก็บข้อมูลถาวร** Kimi Agent สามารถสร้างได้ทั้งสามส่วน แต่การทำงานได้สำเร็จขึ้นอยู่กับการตั้งค่าสภาพแวดล้อม การกำหนดค่าการยืนยันตัวตน และการดำเนินการเผยแพร่
</Callout>

หากแอปของคุณทำงานไม่เป็นไปตามที่คาดไว้ ปัญหามักไม่ได้เกิดจากความสามารถของแบ็กเอนด์ที่ขาดหายไป แต่มักมาจากขั้นตอนการพรีวิว การยืนยันตัวตน ฐานข้อมูล หรือการเผยแพร่ที่ยังไม่สมบูรณ์

## ขั้นตอนการทำงานแบบ full-stack

1. **สร้าง**: Agent สร้างส่วนหน้า + แบ็กเอนด์ + โครงสร้างฐานข้อมูลและตรรกะข้อมูล
2. **พรีวิว**: รันใน sandbox เพื่อทดสอบ full-stack ในเครื่อง (บางกรณีอาจต้องเริ่มทำงานด้วยตนเอง)
3. **เวอร์ชัน**: Agent สามารถใช้เครื่องมือจัดการเวอร์ชันและสร้าง commit ได้อัตโนมัติ
4. **ย้อนกลับ**: คุณสามารถย้อนกลับไปยังเวอร์ชัน commit ก่อนหน้าใดก็ได้
5. **เผยแพร่ / แชร์**: แอปจะถูกดีพลอยไปยัง URL สาธารณะหลังจากที่คุณเผยแพร่ด้วยตนเองเท่านั้น

## สาเหตุที่พบบ่อยของความล้มเหลว

| อาการ | สาเหตุที่เป็นไปได้ | สิ่งที่ควรทำ |
|----------|-------------|------------|
| ส่วนหน้าโหลดได้แต่ API ล้มเหลว | sandbox runtime ยังไม่เริ่มทำงาน | เริ่ม sandbox แล้วรันพรีวิวใหม่ |
| ข้อมูลไม่ถูกบันทึกหรือไม่แสดง | ฐานข้อมูลยังไม่ได้เริ่มต้นหรือ migrate | รันขั้นตอนการตั้งค่าหรือ migration ของฐานข้อมูลใหม่ |
| เข้าสู่ระบบไม่สำเร็จ | ตั้งค่า auth flow ไม่ถูกต้อง | ตรวจสอบการกำหนดค่า Kimi Login และการตั้งค่า callback |
| ผู้อื่นเข้าถึงแอปของคุณไม่ได้ | แอปยังไม่ถูกเผยแพร่ | คลิก **เผยแพร่/แชร์** เพื่อดีพลอย |
| การเปลี่ยนแปลงล่าสุดทำให้ฟังก์ชันเสีย | เกิด regression ในเวอร์ชันล่าสุด | ย้อนกลับไปยัง commit ที่เสถียร |

## การรองรับการยืนยันตัวตน

- **ระยะที่ 1**: รองรับ **Kimi Login**
- **ระยะถัดไป**: จะเพิ่มผู้ให้บริการ OAuth เพิ่มเติม
- **รองรับด้วยเช่นกัน**: Agent สามารถสร้างการเข้าสู่ระบบด้วยบัญชีอีเมล/รหัสผ่านแบบมาตรฐานที่ใช้ฐานข้อมูลได้

## เวอร์ชันและการย้อนกลับ

- Agent รองรับเครื่องมือจัดการเวอร์ชันใหม่ และสามารถ `git commit` ได้เองในระหว่างการพัฒนา
- คุณสามารถดูประวัติเวอร์ชันและย้อนกลับไปยัง commit ที่เลือกได้เมื่อจำเป็น

## พรีวิว vs เผยแพร่

- **พรีวิว**: สำหรับการพัฒนาและทดสอบใน sandbox อาจต้องเริ่ม sandbox ด้วยตนเองในบางสถานการณ์
- **เผยแพร่/แชร์**: การดำเนินการด้วยตนเองของผู้ใช้ที่ดีพลอยแอปของคุณไปยังสภาพแวดล้อมที่เข้าถึงได้แบบสาธารณะ

## Agent เหมาะที่สุดสำหรับ

- การสร้างต้นแบบผลิตภัณฑ์ full-stack อย่างรวดเร็ว
- ขั้นตอน CRUD ที่มีพื้นที่จัดเก็บข้อมูลถาวร
- การจัดการข้อมูลพื้นฐานสำหรับงานแอดมินหรือหลังบ้าน
- โปรเจกต์เดโมแบบ end-to-end ที่มีการเข้าสู่ระบบ ข้อมูล และขั้นตอนการดีพลอย

## ข้อจำกัดในปัจจุบัน

- การดำเนินงาน production ขั้นสูง (เช่น SRE ที่ซับซ้อนและ HA แบบหลายภูมิภาค) ยังคงต้องอาศัยงานวิศวกรรมด้วยตนเอง
- สำหรับสถานการณ์ production ที่มีความเสี่ยงสูง ควรตรวจสอบความปลอดภัยและเสริมความแข็งแกร่งของการดีพลอยก่อนเผยแพร่
