## 选择模型

Kimi 提供多款模型。点击输入框上方的模型切换按钮即可切换。

| 模型 | 思考强度 | 适用场景 |
|-------|-------------------|----------|
| **K2.6** | 标准 / 进阶 | 快速对话与问答，响应更迅速 |
| **K3** | 基础 / 进阶 / 极致 | 对话与 Agent 任务；综合能力最强 |
| **K3 Swarm** | 基础 / 进阶 / 极致 | 大规模搜索与批量处理，一次性完成 |

<Callout type="tip">
K2.6 不消耗额度；K3 和 K3 Swarm 按额度计费。详见[会员权益](https://www.kimi.com/help/membership/membership-overview)。
</Callout>

### 关于 Kimi K3

Kimi K3 是目前 Kimi 最强大的模型，拥有 2.8 万亿参数，基于 Kimi Delta Attention（KDA）与 Attention Residuals 构建，具备**原生视觉**能力和 **100 万 token 的上下文窗口**。作为全球首个开源的 3T 级模型，K3 面向长程代码、知识工作与推理等前沿智能场景设计，在代码、长程任务执行以及广泛的通用智能任务中均达到领先水平。

### 内置工具

开箱即用，无需配置：

| 工具 | 说明 |
|------|------------|
| **Web Search** | 实时网页搜索，获取最新新闻和信息 |
| **抓取工具** | 直接访问指定 URL（网页、文档、图片及其他在线资源） |
| **图片搜索** | 支持以文搜图、以图搜图，快速发现视觉内容 |
| **IPython** | 执行 Python 代码，用于数据分析与可视化 |
| **记忆** | 智能记忆你的个人偏好和使用习惯 |

## 视觉与多模态能力
Kimi K3 支持对图片、视频和办公文档（PDF/Word/Excel）的全场景理解，采用**原生多模态架构**（并非外接 OCR）。它可以直接解析文档内容，并完成中高级办公任务（例如编写 Excel 公式，或生成 PPT 大纲/VBA 代码）。结合原生视觉能力和 100 万 token 的上下文窗口，它可以处理更长、更复杂的多模态素材。
### 多模态输入支持
- **图片**：PNG、JPEG、WebP、GIF 等（通过 URL、Base64 或本地文件上传）
- **视频**：MP4 等（通过 video_url，或图片帧序列 + fps 参数）
- **文档**：PDF、Word、Excel、TXT、Markdown 等
- **在线资源**：URL、文章链接
- **图片搜索**：上传图片，搜索相关或相似图片
- **视频理解**：支持视频理解，可分析屏幕录制并复现交互逻辑
- **视觉编码**：上传截图或屏幕录制即可生成前端代码（HTML/Vue/React 等）；也可根据设计稿自动复现网页

### 输出格式
- 纯文本 / 图文混排：标准对话回复
- Markdown：包含标题、列表、表格和链接的富文本
- 代码块：HTML/Vue/React/Python/JSON/Mermaid 等（带语言标识符）
- JSON 结构化数据：强制 JSON 模式输出
- Mermaid 图表：流程图、时序图、思维导图等
- LaTeX 数学公式：行内和块级数学表达式
- 双模式输出（Thinking）：同时返回 `reasoning_content`（思考过程）和 `content`（最终答案）
- 工具调用格式：Function Calling 标准格式（面向开发者）

### 重要说明

1. **文件输出**：K3 可端到端生成可编辑文档（例如 `.pptx`、`.docx`、`.xlsx`、`.pdf`）等复杂交付物；K2.6 专注于快速问答，仅输出文本（例如 PPT 大纲、Word 正文或代码）。

<Callout type="tip">
提示：如需生成图片、音频或视频，请点击“+”→ 插件，选择相应功能，并搭配 **K3** 使用。如需创建复杂的可编辑文档或运行多步骤任务，建议选择 **K3** 或 **K3 Swarm** 以获得完整体验。
</Callout>

## 会话与对话轮次
点击“新对话”时，可以把它理解为与 Kimi 开启了一场较长的对话。
| 概念 | 类比 | 技术定义 |
|---------|---------|---------------------|
| **会话** | 一整场会议（从开始到结束） | 一次完整的聊天过程，有明确的开始和结束 |
| **轮次** | 一次往返交流（你发言，Kimi 回复） | 你的输入和 Kimi 的回复构成一个往返 |

### 主要区别
**会话**
- **连续记忆**：Kimi 会记住当前聊天中的全部上下文
- **跨轮上下文**：每次回复都会参考此前的对话内容，并将其作为下一轮的上下文
- **边界明确**：点击“新对话” = 重新开始；此前上下文会被清除
**轮次**
- **累计计数**：第 1 轮、第 2 轮……逐步增加
- **记忆有限**：轮次过多（例如 50+）时，Kimi 可能会“忘记”较早的内容，尤其是在长篇写作或要求严格的任务中
- **上下文长度约束**：受 token 数量限制；轮次不断累积时，最早的内容可能会被压缩

<Callout type="tip">
**特殊情况**：如果一次问答就结束了对话，那么 1 轮 = 1 个会话。
</Callout>

## 为什么这个区别很重要
在同一个会话中，你发送的每个新问题或指令，都会参考此前所有轮次来作答。随着轮次增多、内容变长，回复质量可能会逐渐下降。

### 常见场景
**场景 1：切换话题**
- 不建议：在一个已经用来写 30,000 字小说的会话里，继续提问“帮我计算税务”
- 建议：为税务问题开启新会话，避免 Kimi 把小说人物和税务概念混在一起
**场景 2：处理长文档**
- 经过几十轮对话后，Kimi 可能会“忘记”一开始设定的规则或文件摘要
- 解决方法：在任务进行中主动总结（“总结一下目前为止的计划”），或开启新会话
**场景 3：理解产品限制**
- 上下文长度限制以 token 衡量，但在日常使用中，可以近似理解为“轮次”
- 如果看到“开启新对话”的提示，说明当前会话轮次已经过多
## 最佳实践

<Callout type="tip">
**每个任务开启一个新会话**：写作、研究、调试等独立任务应分别使用独立会话，避免上下文相互干扰。
</Callout>

<Callout type="tip">
**长会话中定期总结**：超过 20 轮后，主动请 Kimi 总结关键信息，避免信息丢失。
</Callout>

<Callout type="tip">
**及时清理敏感信息**：聊天记录会被保留；处理完私人内容后，请删除整个会话。
</Callout>
