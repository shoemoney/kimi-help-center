# Kimi 网页常见问题

> 如需了解预览面板按钮、编辑模式、发布与取消发布等完整说明，请参阅 [Kimi 网页](/websites/websites-overview)。本页仅介绍常见故障排查方法。

## 预览无法加载，或看不到最新版本？

> 例如：“网站没有显示出来”“预览还是旧版本”，或“看不到最新保存的版本”。

多数情况下，网站其实已经成功生成并保存。“看不到”的问题通常出在预览面板或版本卡片的显示上。最常见的原因是项目目录不正确。其他情况可按以下顺序处理：

<Callout type="warning">
**请确认项目目录**：网站项目必须位于 `/mnt/agents/output/app`。预览只会读取从该目录保存的版本。如果 Kimi 将项目放在其他位置（例如临时 `/tmp` 目录），版本可能已经保存成功，但预览无法读取——请让 Kimi 将项目移动到该目录后重新保存。
</Callout>

1. **刷新页面或重新打开对话**——版本卡片有时需要几秒钟才会显示。
2. **请 Kimi 在对话中保存一个新版本。**
3. **如果对话非常长，建议尝试开启新对话**（见下方“我的对话很长——需要开启新对话吗？”）。
4. 如果仍未显示：通常代码和版本已经成功保存（你可以向 Kimi 询问版本号）。这往往是预览服务的临时波动——请稍后重试。若问题持续存在，请点击预览面板中的**用户反馈**（信封图标），提交反馈并附上版本号，我们的团队会进一步排查。

## 网站空白、白屏、崩溃或无响应？

> 例如：“页面完全空白”“网站是空的”“网站崩溃了”，或“什么都不显示 / 点击没有反应”。

- 空白或崩溃通常由**前端运行时错误**导致（例如依赖缺失、直接访问子页面，或某个资源/图片加载失败）。请在对话中向 Kimi 描述症状（附上截图会更有帮助），它会定位并修复问题，然后保存新版本。
- 如果你怀疑白屏是由**文件缺失**造成的，每个网站版本都会保存快照。请 Kimi 从历史版本恢复（见下方“项目文件或目录缺失”）。
- **浏览器兼容性**：部分注重隐私保护的浏览器（如 Brave、某些 Firefox 插件）可能会阻止前端资源加载，导致显示异常。你可以尝试将 Kimi 域名加入白名单，临时关闭防护/隐私拦截功能，或改用 Chrome / Edge / Safari。

## 点击“发布”失败怎么办？

处理方式与上文相同：稍后重试。若问题持续存在，请通过**用户反馈**提交，并附上版本号。该版本通常已经成功保存，无需从头重新构建。

## 网站链接有效期多久？会过期吗？

如果你点击**发布**将网站公开部署，生成的链接会长期有效，除非你手动点击**取消发布**将网站设为私密，或内容因违规被标记处理。

## 内容、数据或记录缺失？

> 例如：“我的首页内容消失了”“我上传到数据库的知识不见了”“我上传的信息丢失了”，或“AI 说数据永久丢失”。

多数情况下，数据并未真正丢失。请按以下顺序确认：

1. **首先确认网站是否真正是“全栈”**：只有具备**后端（数据库）能力**的全栈网站，才会把数据存储在平台的云数据库中，并在不同访问和设备之间保留。实际使用中，许多声称是“全栈”的网站**最终其实只是前端网站**，数据从未真正进入数据库——这种情况下，刷新页面或切换设备后，先前的数据自然会消失。请让 Kimi 确认项目是否包含真实的后端和数据库。
2. **纯前端网站**：数据只保存在当前浏览器的本地存储（localStorage）中。更换浏览器/设备，或清除浏览器数据，都会导致数据丢失。如果你需要长期、多设备保留数据，请让 Kimi 改为带数据库的全栈方案。
3. **已确认是全栈网站**：数据会保存在平台托管的云数据库中。**发布新版本不会清空已有数据**；如果明明是全栈但数据仍不可见，通常是临时问题——请刷新或稍后重试。
4. **如果你确认数据确实丢失**：请点击预览面板中的**用户反馈**（信封图标）提交反馈，我们的团队会进一步排查。此时请不要继续反复操作，以免发生覆盖。

## 项目文件或目录缺失，或出现“环境重置”/“无法恢复”？

> 例如：“我的网站项目目录不见了，无法恢复”“文件缺失”，或“出现环境重置提示”。

- 每个网站版本都会**保存快照**，因此源代码通常可以从历史版本中恢复。请 Kimi 列出历史版本，并回滚/恢复到指定版本。
- 如果这种情况发生在**非常长的对话**中（尤其是你在对话中途切换过模型），建议开启新对话（见下一项）。
- 如果仍无法恢复，请点击**用户反馈**提交反馈，我们的团队会进一步排查。

## 我的对话很长——需要开启新对话吗？

如果一段对话持续了很久、跨越了许多版本，或你在对话中途切换过模型（例如 K2.6 → K3），当前能力可能不是最新版本，从而导致上下文丢失或文件异常。**建议开启新对话**，以获得最新的构建和交付能力。已发布的网站和历史版本不受影响，仍可正常访问。

## 导出代码后可以自行部署吗？

你可以下载完整项目代码并部署到自己的服务器，但以下两项由 Kimi 平台提供，**不会随代码一起迁移**：

- **Kimi 账号登录**：这是平台提供的登录能力，离开 Kimi 平台后无法直接使用。如果自部署也需要登录功能，请让 Kimi 基于你自己的数据库实现用户名/密码登录系统。
- **平台托管数据库**：全栈网站的数据会保存在平台为该网站分配的云数据库中。导出的代码不包含这些数据，也不会自动连接到你自己的数据库。自部署需要自行搭建数据库并迁移数据。

如果你只是希望网页可被公开访问，直接使用平台的**分享 → 发布**功能即可。无需自行搭建服务器——Kimi 账号登录和云端数据仍会正常工作。

## 生成的网站不符合我的需求？

- 在对话中明确指出不符合预期的地方：例如颜色、布局、文案、功能模块、数据表等。
- 你可以上传参考图片、示例网页，或提供更详细的文字说明，让 Agent 按参考修改。
- 如果多次修改后仍不满意，建议用更结构化的需求描述开启新对话。

## 生成后还能修改网站内容、链接或样式吗？

可以。在原对话中继续告诉 Agent 你想修改的内容，例如：

- “把首页标题改成 XXX”
- “把‘联系我们’按钮链接改为 https://xxx”
- “整体切换为深色主题”

修改完成后，Agent 会重新生成并部署一个新链接。

## 如何给网站添加后端、数据库或登录功能？

- 在建站指令中明确强调，你需要一个带数据库和登录功能的全栈网页。
- 也可以先让 Agent 生成前端页面，再导出源代码交给开发者进行二次开发。

## 可以下载网站源代码，或导出到 GitHub 吗？

当前版本支持将所有文件下载到本地。在对话中打开“所有文件”，然后点击下载按钮。

## 生成/修改网站会消耗多少额度？

网站生成是一项复杂任务，通常会消耗较多 tokens/额度，具体取决于：

- 页面数量和复杂度
- 是否包含图片、表格和交互逻辑
- 深度修改的次数

建议尽量清晰地描述需求，以减少反复试错。如果你对结果不满意，可以在反馈中说明情况。

## 网站生成很慢、一直排队，或终端失败？

- 高峰时段（工作日白天和晚上）可能会出现排队。建议在非高峰时段使用。
- 如果任务卡住超过 10 分钟，请先尝试刷新网页。
- 对于复杂网站，建议拆分为更小的任务：先做首页，再逐步添加子页面和功能。

## Kimi 网页适合做什么？不适合做什么？

**适合：**

- 个人主页/作品集、活动落地页、产品展示页、简单工具页、小游戏原型
- 快速验证设计想法，并生成可交互演示
- 需要简单后端数据库和用户系统的网站

**不适合：**

- 带支付系统的复杂网站
- 高并发、高可用的正式生产环境
- 需要自定义域名并长期稳定托管的商业网站
