# 为什么无法正常运行？

<Callout type="tip">
全栈项目包含**前端 UI、后端服务和持久化存储**。Kimi Agent 可以生成这三者，但能否顺利运行，取决于环境设置、认证配置和发布操作是否到位。
</Callout>

如果你的应用没有按预期运行，通常不是因为缺少后端能力，而是预览、认证、数据库或发布步骤尚未完整完成。

## 全栈工作流程 

1. **生成**：Agent 创建前端 + 后端 + 数据库结构，以及数据逻辑。
2. **预览**：在沙箱中运行，进行本地全栈测试（某些情况下可能需要手动启动）。
3. **版本**：Agent 可使用版本工具，并自动创建提交。
4. **回滚**：你可以回到任意历史提交版本。
5. **发布 / 分享**：只有在你手动发布后，应用才会部署到公开 URL。

## 常见故障原因 

| 现象 | 可能原因 | 处理方法 |
|----------|-------------|------------|
| 前端能加载，但 API 失败 | 沙箱运行时未启动 | 启动沙箱并重新预览 |
| 数据没有保存或不可见 | 数据库未初始化或未迁移 | 重新执行数据库设置或迁移步骤 |
| 登录失败 | 认证流程配置不正确 | 检查 Kimi 登录配置和回调设置 |
| 其他人无法访问你的应用 | 应用尚未发布 | 点击**发布/分享**进行部署 |
| 最近的改动破坏了功能 | 最新版本出现回归问题 | 回滚到稳定的提交版本 |

## 认证支持

- **阶段 1**：支持 **Kimi 登录**。
- **下一阶段**：将加入更多 OAuth 提供方。
- **同时支持**：Agent 可以生成标准的基于数据库的邮箱/密码账号登录。

## 版本与回滚

- Agent 支持新的版本工具，并可在开发过程中自主执行 `git commit`。
- 你可以查看版本历史，并在需要时回滚到指定提交。

## 预览与发布

- **预览**：用于在沙箱中开发和测试；某些场景下可能需要手动启动沙箱。
- **发布/分享**：由用户手动执行，将应用部署到可公开访问的环境。

## Agent 最适合

- 快速搭建全栈产品原型
- 带持久化存储的 CRUD 流程
- 基础管理后台或内部数据操作
- 包含登录、数据和部署流程的端到端演示项目

## 当前边界

- 高级生产运维（例如复杂的 SRE 和多区域 HA）仍需要人工工程投入。
- 对于高风险生产场景，请在发布前完成安全审查和部署加固。
