## 選擇模型

Kimi 提供多種模型。點擊輸入框上方的模型切換按鈕即可切換。

| 模型 | 思考強度 | 適用情境 |
|------|----------|----------|
| **K2.6** | Standard / High | 快速對話與問答，回應更迅速 |
| **K3** | Low / High / Max | 對話與 Agent 任務；整體能力最強 |
| **K3 Swarm** | Low / High / Max | 大規模搜尋與批次處理，一次完成 |

<Callout type="tip">
K2.6 不消耗額度；K3 與 K3 Swarm 依額度計費。詳情請參閱[會員權益](https://www.kimi.com/help/membership/membership-overview)。
</Callout>

### 關於 Kimi K3

Kimi K3 是目前 Kimi 最強大的模型，擁有 2.8 兆參數，建構於 Kimi Delta Attention（KDA）與 Attention Residuals 之上，具備**原生視覺**與 **100 萬 token 上下文視窗**。作為全球首個開源的 3T 級模型，K3 專為長週期程式撰寫、知識工作與推理等前沿智慧任務打造，在程式撰寫、長週期執行與各類通用智慧任務中皆達到頂尖表現。

### 內建工具

開箱即用，無需設定：

| 工具 | 說明 |
|------|------------|
| **Web Search** | 即時網路搜尋最新新聞與資訊 |
| **擷取工具** | 直接存取特定 URL（網頁、文件、圖片與其他線上資源） |
| **圖片搜尋** | 以文字搜圖、以圖搜圖，快速探索視覺內容 |
| **IPython** | 執行 Python 程式碼，用於資料分析與視覺化 |
| **記憶** | 智慧記憶，記錄你的個人偏好與使用習慣 |

## 視覺與多模態能力
Kimi K3 支援對圖片、影片與辦公文件（PDF/Word/Excel）的全場景理解，採用**原生多模態架構**（不是外掛式 OCR）。它可以直接解析文件內容，並執行中高階辦公任務（例如撰寫 Excel 公式，或生成 PPT 大綱／VBA 程式碼）。結合原生視覺與 100 萬 token 上下文視窗，還能處理更長、更複雜的多模態素材。
### 多模態輸入支援
- **圖片**：PNG、JPEG、WebP、GIF 等（透過 URL、Base64 或本機檔案上傳）
- **影片**：MP4 等（透過 video_url，或圖片影格序列 + fps 參數）
- **文件**：PDF、Word、Excel、TXT、Markdown 等
- **線上資源**：URL、文章連結
- **圖片搜尋**：上傳圖片以搜尋相關或相似圖片
- **影片理解**：支援影片理解——可分析螢幕錄影並複現互動邏輯
- **視覺程式撰寫**：上傳螢幕截圖或螢幕錄影以生成前端程式碼（HTML/Vue/React 等）；可依設計稿自動還原網頁

### 輸出格式
- 純文字／圖文混合：標準對話式回覆
- Markdown：包含標題、清單、表格與連結的富文字
- 程式碼區塊：HTML/Vue/React/Python/JSON/Mermaid 等（含語言識別碼）
- JSON 結構化資料：強制以 JSON mode 輸出
- Mermaid 圖表：流程圖、時序圖、心智圖等
- LaTeX 數學公式：行內與區塊層級的數學表達式
- 雙模式輸出（Thinking）：同時回傳 `reasoning_content`（思考過程）與 `content`（最終答案）
- 工具呼叫格式：Function Calling 標準格式（供開發者使用）

### 注意事項

1. **檔案輸出**：K3 可端到端產出可編輯的文件（例如 `.pptx`、`.docx`、`.xlsx`、`.pdf`）等複雜交付成果；K2.6 則聚焦於快速問答，僅輸出文字內容（例如 PPT 大綱、Word 內文或程式碼）。

<Callout type="tip">
提示：若要生成圖片、音訊或影片，請點擊「+」→ Plugin，選擇對應功能，並搭配 **K3** 使用。若要製作複雜且可編輯的文件，或執行多步驟任務，建議選擇 **K3** 或 **K3 Swarm** 以獲得完整體驗。
</Callout>

## Session 與對話回合
當你點擊「新聊天」時，可以把它想成是和 Kimi 開始一段長對話。
| 概念 | 類比 | 技術定義 |
|---------|---------|---------------------|
| **Session** | 一整場會議（從開始到結束） | 一個有明確起點與終點的完整聊天流程 |
| **回合** | 一次往返（你發言，Kimi 回覆） | 你的輸入與 Kimi 的回應構成一次來回 |

### 主要差異
**Session**
- **連續記憶**：Kimi 會記住目前聊天中的所有上下文
- **跨回合上下文**：每次回覆都會參照先前的對話內容，作為下一回合的上下文
- **邊界明確**：點擊「新聊天」= 重新開始；先前上下文會被清除
**回合**
- **累計計數**：第 1 回合、第 2 回合……依序增加
- **記憶有限**：回合太多（例如 50+）可能會讓 Kimi「忘記」較早的內容，尤其是在長文寫作或有嚴格要求的任務中
- **上下文長度限制**：受 token 數限制；當回合累積時，最早的內容可能會被壓縮

<Callout type="tip">
**邊界情況**：如果一次問答就結束了對話，那麼 1 回合 = 1 個 session。
</Callout>

## 為什麼這項區分很重要
在同一個 session 中，你送出的每個新問題或指令，都會參照先前所有回合來回答。隨著回合累積、內容變長，回覆品質可能會逐漸下降。

### 常見情境
**情境 1：切換主題**
- 錯誤做法：在一個已經用來撰寫 30,000 字小說的 session 裡，詢問「幫我計算稅金」
- 正確做法：為稅務問題開啟新的 session，避免 Kimi 把小說角色和稅務概念混在一起
**情境 2：處理長文件**
- 經過數十個回合後，Kimi 可能會「忘記」一開始建立的規則或檔案摘要
- 解法：在任務進行中主動摘要（「總結一下我們目前的計畫」），或開啟新的 session
**情境 3：理解產品限制**
- 上下文長度限制是以 token 衡量，但日常使用時，可以把它理解為「回合數」
- 如果你看到「開始新的聊天」提示，表示目前 session 的回合數已經太多
## 最佳實務

<Callout type="tip">
**每個任務使用新的 session**：彼此獨立的任務——寫作、研究、除錯——都應各自開一個 session，避免上下文互相干擾。
</Callout>

<Callout type="tip">
**長 session 定期摘要**：超過 20 回合後，主動請 Kimi 摘要關鍵資訊，避免資料遺失。
</Callout>

<Callout type="tip">
**及時清理敏感資訊**：聊天記錄會被保留；處理私人內容後，請刪除整個 session。
</Callout>
