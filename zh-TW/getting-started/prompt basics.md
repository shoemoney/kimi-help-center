# 提示詞基礎

<Callout type="info">
提示詞是你傳送給 Kimi 的文字指令——可以是一個問題、一段描述、一組要求，甚至是一份完整的任務簡報。Kimi 會根據你的提示詞理解意圖、組織回答並執行任務。

簡單來說：**你怎麼問，決定 Kimi 怎麼答。** 清楚、具體的提示詞，幾乎總能帶來更準確、更有價值的回覆。
</Callout>

## 好提示詞的四個核心要素

### 1. 說明角色與情境

告訴 Kimi 你是誰、處在什麼情境，有助於它掌握合適的深度與語氣。

| 模糊的提示詞 | 更好的提示詞 |
|-------------|--------------|
| 寫一篇關於 AI 的文章 | 我是科技媒體編輯。需要一篇面向一般讀者的 2,000 字 AI 科普文章，風格要易懂且有吸引力 |
| 幫我分析資料 | 我是市場分析師。請分析這份 Excel 檔案中各通路的轉換率，重點放在月對月變化 |

### 2. 具體描述任務

描述越具體，需要反覆修改的次數就越少。一個好的任務描述通常包含：

- **要做什麼**：明確的動作（分析、摘要、翻譯、生成、比較……）
- **輸出格式**：表格、清單、段落、程式碼、Markdown……
- **範圍與限制**：字數、項目數量、時間範圍、地理範圍……
- **品質要求**：學術語氣、口語自然、精簡、詳細……

### 3. 提供範例或參考

如果你對格式有明確期待，給 Kimi 一個範例（few-shot）會非常有效：

<CodePreview

    },
  ]}
/>

### 4. 將複雜任務拆成步驟
面對複雜任務時，把工作拆成較小的步驟，並引導 Kimi 逐步完成：

<CodePreview
  files={[
    {
      name: "prompt.txt",
      language: "text",
      content: "我需要一份競品分析報告。請依照以下步驟進行：\n列出國內前 3 名競爭對手及其核心功能\n比較它們的定價策略\n分析各產品的優勢與劣勢\n為我們的產品提出差異化建議",
    },
  ]}
/>

## 實用技巧
### 善用追問與迭代
第一次回答不夠滿意？直接追問即可，不必重述所有背景：
- "請進一步說明第 2 點"
- "語氣再正式一點"
- "加入資料來源"
- "換個角度重新分析"
### 善用檔案與連結
Kimi 支援上傳 PDF、Word 文件、Excel 檔案、圖片等。你也可以直接貼上 URL。將檔案與提示詞結合，能大幅提升效率：
| 任務 | 提示詞範例 |
|------|---------------|
| 摘要 PDF | "摘要這份 PDF 的重點" |
| 分析資料 | "根據這份 Excel 資料分析銷售趨勢" |
| 從 URL 擷取 | "閱讀連結中的這篇文章，並擷取關鍵結論" |

### 指定輸出格式
明確告訴 Kimi 你想要的格式：
| 需求 | 提示詞範例 |
|------|---------------|
| 比較表 | "用表格比較 A 和 B 的優缺點" |
| 程式碼輸出 | "用 Python 實作，並加上註解" |
| 結構化清單 | "整理成編號清單，每項不超過 20 個字" |
| Markdown | "以 Markdown 格式輸出，並包含標題層級" |

### 使用記憶保存長期偏好
如果你有經常使用的偏好與要求，可以使用 Kimi 的 **記憶** 功能長期保存：
- "記住我是偏好 React 技術棧的前端工程師"
- "永遠用英文並以 Markdown 格式回覆"
- "回答技術問題時請包含程式碼範例"

<Callout type="tip">
這樣你就不必一再重複說明——Kimi 會在未來對話中自動套用這些偏好。
</Callout>

## 常見錯誤
| 錯誤 | 更好的做法 |
|---------|----------------|
| 把多個不相關任務塞進同一則訊息 | 每個獨立任務都開啟新的對話，保持上下文乾淨 |
| 提示詞過於模糊（例如：「幫我寫點東西」） | 說清楚要寫什麼、寫給誰看、使用什麼風格，以及多長 |
| 期待第一次就得到完美輸出 | 先生成草稿，再透過追問逐步迭代 |
| 不查證 AI 輸出 | 務必確認日期、資料與事實性陳述 |
