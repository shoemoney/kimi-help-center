# 為什麼無法運作？

<Callout type="tip">
全端專案包含**前端 UI、後端服務與持久化儲存**。Kimi Agent 可以生成這三者，但能否順利執行，取決於環境設定、驗證配置與發布操作是否完成。
</Callout>

如果你的應用程式未如預期運作，問題通常不是缺少後端能力，而多半是預覽、驗證、資料庫或發布步驟尚未完整完成。

## 全端工作流程 

1. **生成**：Agent 會建立前端 + 後端 + 資料庫 schema 與資料邏輯。
2. **預覽**：在 sandbox 中執行本機全端測試（某些情況可能需要手動啟動）。
3. **版本管理**：Agent 可使用版本工具並自動建立 commit。
4. **回復版本**：你可以回到任一先前的 commit 版本。
5. **發布／分享**：只有在你手動發布後，應用程式才會部署到公開 URL。

## 常見失敗原因 

| 症狀 | 可能原因 | 處理方式 |
|----------|-------------|------------|
| 前端已載入，但 API 失敗 | Sandbox runtime 尚未啟動 | 啟動 sandbox 後重新預覽 |
| 資料未儲存或看不到 | DB 尚未初始化或遷移 | 重新執行 DB 設定或 migration 步驟 |
| 登入失敗 | 驗證流程設定不正確 | 檢查 Kimi Login 設定與 callback 設定 |
| 其他人無法存取你的應用程式 | 應用程式尚未發布 | 點選**發布／分享**進行部署 |
| 最近的變更導致功能損壞 | 最新版本出現回歸問題 | 回復到穩定的 commit |

## 驗證支援

- **階段 1**：支援 **Kimi Login**。
- **下一階段**：將加入更多 OAuth provider。
- **同時支援**：Agent 也能生成標準的 DB-based email/password 帳號登入。

## 版本與回復

- Agent 支援新版版本工具，並可在開發過程中自主執行 `git commit`。
- 你可以查看版本歷史，並在需要時回復到指定的 commit。

## 預覽與發布

- **預覽**：用於在 sandbox 中開發與測試；某些情境下可能需要手動啟動 sandbox。
- **發布／分享**：由使用者手動執行，將你的應用程式部署到可公開存取的環境。

## Agent 最適合

- 快速打造全端產品原型
- 具備持久化儲存的 CRUD 流程
- 基礎管理後台或內部資料作業
- 涵蓋登入、資料與部署流程的端到端示範專案

## 目前邊界

- 進階生產環境維運（例如複雜的 SRE 與多區域 HA）仍需要人工工程處理。
- 高風險生產情境在發布前，請先完成安全審查與部署強化。
